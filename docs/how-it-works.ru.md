# Как устроен Job Finder — объяснение по-человечески

Этот файл — для меня, автора проекта. Его можно читать сверху вниз за 15 минут. Код тут почти не
цитируется: цель — понять, **что происходит и где это лежит**, а не выучить каждую строчку. Если
понадобится подробность — открываешь нужный файл, он короткий.

---

## 1. Приложение в одном абзаце

Нажимаешь ярлык → в первый раз короткий мастер спрашивает резюме, уровень и языки (потом всё это
меняется в окне Settings) → открывается окно → приложение само скачивает свежие вакансии с семи источников →
выкидывает те, где нет ни одного твоего навыка → оставшиеся по одной отдаёт локальной нейросети
(она работает на твоей видеокарте через LM Studio) → нейросеть ставит оценку 1–10 и пишет, что у
тебя есть и чего не хватает → в окне появляются вакансии с оценкой от 5, лучшие сверху. Всё
запоминается в одном файле базы, поэтому в следующий раз оцениваются только новые вакансии.

---

## 2. Путь одной вакансии: от сайта до строчки в таблице

```
  сайт (Himalayas, junior.guru, …)
        │  1. скачать                       sources.py
        ▼
  запись Job: ссылка, название, компания, место, дата, описание
        │  2. сохранить в базу              db.py   → jobs.db
        ▼
  есть ли в тексте хоть один твой навык?    skills.py
        │  нет → не оцениваем
        ▼  да
  нейросеть: оценка + разбор                llm.py  → LM Studio
        │  3. сохранить оценку              db.py
        ▼
  оценка ≥ 5?  → строчка в таблице «Found»  window.py
```

Всё это делает **фоновый поток** (`worker.py`): пока он работает, окно не зависает, а каждая
оценённая вакансия сразу появляется в таблице.

## 3. Какие файлы за что отвечают

Папка `job_finder/` — это и есть приложение.

| Файл | Простыми словами |
|---|---|
| `__main__.py` | «Кнопка включения»: если настроек нет, показывает мастер, потом запускает окно; ведёт журнал ошибок, не даёт открыть приложение дважды. |
| `config.py` | Технические настройки: модель, адреса сайтов, пути к файлам. Всё личное — в Settings. |
| `settings.py` | Твои настройки: резюме, навыки, главный навык, город, уровни, языки. Хранятся в базе. Здесь же чтение резюме (md, txt, pdf) и поиск навыков в нём. |
| `settings_window.py` | Мастер первого запуска и окно Settings — одни и те же поля, по шагам или с меню слева. |
| `flow_layout.py` | Раскладка «плашек» навыков: в ряд, с переносом на следующую строку. |
| `sources.py` | Ходит на сайты с вакансиями и превращает их ответы в одинаковые записи `Job`. Убирает дубли. |
| `uradprace.py` | Вакансии Úřad práce: раз в день скачивает их открытый файл, оставляет IT-вакансии твоего края. |
| `hardware.py` | Сколько памяти у видеокарты и какая модель подходит: от 8 ГБ — 8B, меньше — 3B. |
| `ready_window.py` | Окно «Getting ready»: есть ли LM Studio и скачана ли модель, кнопка «Download model». |
| `installer.py` | Установка и удаление собранной версии: папка программы, ярлыки, «Uninstall Job Finder». |
| `skills.py` | Проверяет, есть ли в тексте вакансии хоть один навык из настроек. |
| `llm.py` | Единственное место, где мы говорим с нейросетью: запустить LM Studio, оценить вакансию, выгрузить модель. Здесь же шаблон правил оценки (`RULES_TEMPLATE`): город, уровни и языки подставляются из настроек. |
| `db.py` | Работа с базой `jobs.db`: сохранить вакансии и оценки, достать списки для окна. |
| `worker.py` | «Дирижёр» обновления: скачать → отсеять → оценить. Работает в фоне. |
| `window.py` | Главное окно: таблицы, карточка вакансии, кнопки, вкладки. |
| `cv_window.py` | Окно «My CV» — показывает резюме, по которому идёт оценка. |
| `insights.py` | Вкладка Insights: словарь требований и подсчёт, чего чаще всего не хватает. |
| `style.py` | Цвета и оформление тёмной темы. |

Остальное:

| Что | Зачем |
|---|---|
| `tests/` | Автоматические проверки (больше 150). Запуск: `.venv\Scripts\python -m pytest tests -q`. |
| `install.ps1` | Установка из исходников: создаёт виртуальное окружение, ставит библиотеки, кладёт ярлык на рабочий стол. |
| `build.ps1`, `packaging/` | Сборка `JobFinder-Setup.exe` для друзей (PyInstaller): приложение с Python внутри в одном файле. |
| `docs/superpowers/` | Спецификация и планы — как мы проектировали приложение (история решений). |
| `master_cv.md` | Твоё резюме, если лежит в папке проекта: мастер подставит его сам. Можно выбрать и любой другой файл (.md, .txt, .pdf). **Не попадает в git** (в `.gitignore`). |
| `jobs.db` | База со всеми вакансиями и оценками. Тоже не в git. |
| `cache/uradprace.json` | Сохранённая выборка IT-вакансий Úřad práce (чтобы не качать большой файл каждый раз). Не в git, можно удалить. |
| `job_finder.log` | Журнал: что происходило и какие были ошибки. |

## 4. Откуда берутся вакансии

Семь источников с **открытым API** или лентой — то есть они сами разрешают программам забирать вакансии, без
логина и парсинга страниц:

| Сайт | Что берём |
|---|---|
| junior.guru | вакансии для джунов; оставляем только город из Settings и удалёнку |
| Himalayas | удалёнка, доступная из Чехии, по главному навыку из Settings; уровни — тоже из Settings |
| Jobicy | удалёнка, доступная из Чехии, разработка |
| Working Nomads | последние вакансии категории Development |
| Úřad práce | все вакансии биржи труда ČR (открытые данные MPSV): IT-профессии твоего края, у всех есть зарплата. Офисная работа — берётся и без удалёнки |
| Remote OK | удалёнка; много «только США» — такие нейросеть оценит низко |
| We Work Remotely | удалёнка из разделов программирования и DevOps |

**Úřad práce** выкладывает один файл со всеми вакансиями страны (~190 МБ, обновляется раз в день).
Приложение скачивает его, только если он изменился, читает по кусочку (не загружая целиком в память) и
сохраняет IT-вакансии всех краёв в `cache/uradprace.json`, так что смена города в Settings не требует новой
загрузки. Описания там часто короткие, поэтому отсев по навыкам пропускает не все — оцениваются те, где
навык упомянут.

**Почему нет jobs.cz, prace.cz, LinkedIn, StartupJobs.** У них нет открытого API для такого приложения —
только разбирать их страницы, а это против их правил и ломается при каждом редизайне.

Если какой-то сайт не ответил (например, ошибка **521** — это значит, что упал их сервер), остальные
продолжают работать, а в строке состояния будет написано, какой сайт подвёл. Его вакансии из прошлого
раза остаются. При следующем «Refresh» всё обычно приходит снова.

Одна и та же вакансия на двух сайтах (та же компания + то же название) сохраняется один раз.

**Почему нет ключевых слов.** Сначала поиск был по 1–3 ключевым словам, но их трудно придумать, а
Himalayas при трёх словах отдавал вдвое меньше вакансий: его 10 страниц делились между словами. Теперь
поиск идёт по одному **главному навыку**, который ты выбираешь из своего списка навыков (по умолчанию —
язык программирования, который чаще всех встречается в резюме), и снова на все 10 страниц.

## 5. Как нейросеть ставит оценку

- Модель — **Ministral 3 8B**, работает в LM Studio прямо на видеокарте. Интернет ей не нужен,
  резюме никуда не уходит. Если у видеокарты меньше 8 ГБ, берётся **Ministral 3 3B**: она слабее, оценки
  могут немного отличаться. Объём видеопамяти приложение узнаёт из реестра Windows.
- Приложение само запускает сервер LM Studio и загружает модель, а после оценки выгружает её, чтобы
  освободить видеопамять. Открывать LM Studio руками не нужно.
- Модель получает: **правила** (шаблон в `llm.py`, в него подставлены твой город, уровни и языки) +
  **твоё резюме** + **текст вакансии**.
- Отвечает строго в формате JSON: `score` (1–10), `summary` (почему такая оценка), `have` (что у тебя
  есть), `missing` (чего не хватает), `risks` (что может отсечь).
- Правила учат модель не придираться: длинный список технологий в вакансии — это пожелания, а не
  требования; Django ≈ FastAPI; на junior-позициях и стажировках недостающее — повод учиться. Сильно
  снижать оценку можно только за настоящие блокеры: опыт выше твоего уровня, другой основной язык,
  язык, которого ты не знаешь на нужном уровне, и т. п.
- Одна вакансия — около 8 секунд. Первая полная оценка ~240 вакансий — около 35 минут.

> ⚠️ Если в это время играть на том же компьютере, модель и игра делят видеопамять, и оценка
> может падать по таймауту. Лучше запускать «Refresh», когда видеокарта свободна.

### Почему вакансии иногда оцениваются заново

У каждой оценки есть **ключ** — отпечаток (SHA-256) трёх вещей: текста резюме, правил и названия
модели. Если поменять хоть что-то из этого, старые оценки считаются устаревшими, и при следующем
обновлении всё оценивается заново. Поэтому:

- поправил резюме → будет полная переоценка (~35 мин);
- поменял в Settings город, удалёнку, уровни или языки → тоже (окно сначала спросит и скажет, сколько
  это займёт);
- поменял правила в `llm.py` → тоже;
- поменял навыки или главный навык → **ничего не переоценивается**: просто ищутся и отсеиваются новые
  вакансии по-новому.

## 6. Окно: что где

- **Refresh** — запустить обновление вручную (оно и так запускается при открытии окна).
- **Found** — подходящие вакансии (оценка ≥ 5). «•» и жирный шрифт — новые с прошлого раза,
  «↻» — ты уже подавался на такую же вакансию. Колонка **Posted** — сколько дней вакансии;
  старше 21 дня — серым. «reposted» — сайт «освежил» старую вакансию: обновил дату или выложил её
  заново, а приложение видело её раньше (возраст считается по первому появлению).
- **Над списком** — поиск по названию, компании и месту, фильтр свежести **7d / 14d / 30d / All**
  (по умолчанию 30 дней) и порядок **Best / Newest**. Если фильтр что-то скрыл, внизу написано
  «24 of 25 shown». Фильтры только прячут строки, базу и оценки не трогают.
- **My applications** — твои отклики: нажал **I applied** на вакансии → она переехала сюда. Потом
  отмечаешь **Accepted / Rejected**, пишешь заметки. Если ответа нет больше 14 дней — янтарная
  подсказка «пора напомнить о себе».
- **Insights** — анализ по всем оценённым вакансиям: чего тебе чаще всего не хватает и что вообще
  чаще всего требуют.
- **My CV** — посмотреть резюме, по которому идёт оценка, и навыки для отсева.
- **Settings** — твои настройки: резюме и навыки, город и уровни, языки. Пока идёт обновление, кнопка
  недоступна (обновление читает настройки один раз, в начале).
- **Трей.** Крестик не закрывает приложение, а прячет его в трей (у часов). Оттуда оно раз в 3 часа само
  ищет новые вакансии и, если нашлись новые с оценкой 7+, показывает уведомление Windows. Если в это время
  запущена полноэкранная игра, обновление ждёт 15 минут и пробует снова; если игру запустил посреди
  оценки, оценка встаёт на паузу и выгружает модель. Ярлык на рабочем столе, пока приложение в трее,
  просто открывает его окно. Закрыть совсем — правый клик по иконке → **Quit**.
- Вакансии старше 30 дней нейросеть не оценивает (фильтр свежести по умолчанию — 30 дней — их всё равно
  прячет). Зарплата в
  карточке — только если сайт её дал (Jobicy, иногда Himalayas).
- Справа — **карточка** выбранной вакансии: оценка, почему такая, что есть, чего не хватает, риски,
  описание вакансии (кнопка **Show description**), кнопки **Open job**, **I applied**, **Hide**.
- Нажал **Hide** по ошибке — 10 секунд внизу висит плашка с кнопкой **Undo**.
- Во время оценки в строке состояния видно, сколько примерно осталось (`~25 min left`). Если
  закрыть окно посреди обновления, приложение спросит, точно ли закрыть (уже оценённое сохранено).
- В откликах «⊘» и серая строка «probably filled» — вакансия пропала с сайта, который отдаёт свой
  список целиком (Jobicy, Úřad práce). У Himalayas и Working Nomads такой пометки нет: они отдают
  только последние вакансии, и пропажа там ничего не значит. У junior.guru тоже нет: он только показывает
  вакансии других сайтов (jobs.cz, LinkedIn) и иногда убирает их, пока они ещё открыты. И только пока такие
  вакансии ещё ищутся: если сменить город в Settings или выключить удалёнку, старые отклики этой пометки не
  получат.
- Найденная вакансия, которую источник перестал показывать, ещё неделю остаётся в списке серой с пометкой
  «no longer listed»; в карточке написано, с какого дня. Открой её по ссылке и проверь, открыта ли она. Если
  ту же вакансию выложили заново по новой ссылке, показывается только новая.

## 7. Как работает вкладка Insights

Нейросеть пишет требования свободным текстом, и почти каждая фраза уникальна («cloud platforms
(aws/gcp/azure)», «cloud platform knowledge»…). Поэтому в `insights.py` есть **словарь** примерно из
80 требований с вариантами написания: `Kubernetes` ← kubernetes, k8s, helm… Каждая фраза модели
сводится к названиям из словаря, и дальше просто считается, в скольких вакансиях встретилось.

- «Most often missing» — что модель записала в «Missing». То, что уже есть в твоём разделе Skills,
  сюда не попадает (если модель пишет «commercial Python experience» — это нехватка опыта, а не
  навыка).
- «Most often required» — что встречается в «You have» или «Missing»; зелёная часть полосы — сколько
  раз модель засчитала это тебе.
- Внизу — сколько фраз словарь не узнал. Если какая-то тема часто остаётся нераспознанной — её можно
  добавить в словарь (`REQUIREMENTS` в `insights.py`). Переоценка для этого не нужна.

## 8. Где лежат данные

Всё в одном файле **`jobs.db`** (база SQLite): у тебя (запуск из исходников) — в папке проекта, у
установленной версии — в `%LOCALAPPDATA%\Job Finder` (там же журнал и кэш Úřad práce), поэтому обновление и
удаление программы данные не трогают. Твои настройки — в таблице `settings`
(одна строка). Вакансии — в таблице `jobs`, одна строка — одна вакансия: ссылка, название, компания, место, описание, оценка, разбор модели (JSON), ключ оценки,
статус отклика, дата отклика, заметка, флаги «скрыта» и «просмотрена» и `first_seen` — когда приложение
впервые увидело эту вакансию (или такую же: та же компания и название). По ней ловятся «освежённые»
старые вакансии.

Посмотреть базу глазами можно программой **DB Browser for SQLite** (бесплатная). Если что-то пойдёт
не так, базу можно просто удалить — приложение создаст новую и всё скачает и оценит заново (но
отклики и заметки пропадут, поэтому лучше сделать копию).

## 9. Частые «хочу поменять…»

| Хочу… | Что сделать |
|---|---|
| Обновить резюме | Поправить файл резюме (тот, что выбран в Settings) или выбрать другой. При следующем Refresh всё переоценится. |
| Добавить или убрать навык | Settings → Your CV: плашки с крестиком и поле «+ Add skill». Переоценка не нужна. |
| Искать в другом городе, другого уровня, по другому навыку | Settings: город, «Remote is fine», уровни, главный навык. |
| Порог оценки (5), подсказка «пора напомнить» (14 дней), когда вакансии сереют (21 день) | Сейчас в окне не меняются — стоят значения по умолчанию. Если понадобится, вернём их в Settings. |
| Чтобы искало чаще или реже, уведомляло с другой оценки, оценивало вакансии постарше | `AUTO_REFRESH_HOURS`, `NOTIFY_SCORE`, `OLD_JOB_DAYS` в `config.py`. |
| Чтобы модель оценивала строже или мягче | Текст `RULES_TEMPLATE` в `llm.py`. После правки — полная переоценка. |
| Другую модель | `MODEL` в `config.py` + скачать её в LM Studio (`lms get …`). |
| Научить Insights новому требованию | Добавить строку в `REQUIREMENTS` в `insights.py`, прогнать тесты. |

После любой правки кода полезно прогнать тесты:

```
.venv\Scripts\python -m pytest tests -q
```

Если все «passed» — ничего не сломалось.

## 10. Если что-то сломалось

| Что видишь | Что это значит | Что делать |
|---|---|---|
| `Himalayas: error (521 …)` | сайт временно лёг | подождать и нажать Refresh позже |
| `LM Studio: …` в строке состояния | не запустился сервер или не загрузилась модель | открыть LM Studio, проверить, что модель скачана; посмотреть `job_finder.log` |
| `model … was unloaded … evaluation stopped` | модель выгрузили, пока шла оценка (например, переключил модель в окне чата LM Studio) | просто нажать Refresh ещё раз |
| Оценка очень медленная или падает по таймауту | видеокарта занята (игра, другое приложение) | закрыть тяжёлое приложение и повторить |
| «Job Finder is already open.» | приложение уже запущено (или зависло старое) | найти `pythonw.exe` в диспетчере задач и завершить |
| «Can't read your CV…» | файл резюме переместили или удалили, либо из PDF не достаётся текст (скан) | Settings → Choose file… и выбрать файл заново (PDF — с текстом, не картинкой) |
| «Finish the setup in Settings first» | в настройках чего-то не хватает | открыть Settings: внизу серым написано, чего именно («Still needed») |
| Что-то непонятное | — | открыть `job_finder.log`: там все ошибки с подробностями |

## 11. Словарик

| Слово | Что значит |
|---|---|
| **API** | «окно» сайта для программ: вместо страницы для людей сайт отдаёт данные в удобном для кода виде |
| **JSON** | текстовый формат данных вида `{"score": 7, "have": ["Python"]}` |
| **SQLite** | база данных в одном файле, без отдельного сервера |
| **LLM / нейросеть / модель** | программа, которая читает текст и отвечает текстом; у нас — Ministral 3 8B |
| **LM Studio** | программа, которая запускает модели на твоём компьютере и даёт к ним API |
| **VRAM / видеопамять** | память видеокарты; модель занимает около 6 ГБ из 12 |
| **Фоновый поток** | вторая «линия выполнения»: окно отвечает, пока в фоне идёт долгая работа |
| **Сигнал (Qt)** | способ фонового потока сказать окну «готова новая оценка» |
| **Регулярное выражение** | шаблон для поиска текста, например `k8s|kubernetes` |
| **Хеш (SHA-256)** | короткий «отпечаток» текста: если текст хоть немного изменился, отпечаток другой |
| **Тест (pytest)** | маленькая программа, которая проверяет, что кусок кода работает как надо |
| **venv** | отдельная папка с Python и библиотеками только для этого проекта (`.venv`) |
| **git / коммит** | история изменений проекта; коммит — один сохранённый шаг |

## 12. Как друзья ставят приложение

1. Скачивают `JobFinder-Setup.exe` со страницы релизов на GitHub (собирается `build.ps1`, внутри — Python и
   все библиотеки). Windows предупреждает «неизвестный издатель» — подписи нет, жмут «Подробнее → Выполнить
   в любом случае».
2. Установщик кладёт программу в `%LOCALAPPDATA%\Programs\Job Finder`, делает ярлыки на рабочем столе и в
   «Пуске» и пункт «Uninstall Job Finder».
3. При первом запуске окно **Getting ready** проверяет LM Studio и модель (по объёму видеопамяти: 8B или 3B) и
   даёт скачать модель кнопкой. Если всё есть — окна нет (у тебя его не будет).
4. Дальше обычный мастер настроек.

Версия из исходников и установленная одновременно не запускаются: «уже открыто» общее, и второй запуск просто
открывает окно первой.

## Рецепты: как что-то поменять

Главное, что нужно помнить перед любой правкой: **если меняется модель или `RULES`, все вакансии
переоцениваются** (~37 минут на ~259 вакансий). Всё остальное ниже переоценку не вызывает.

| Хочу… | Что поменять | Переоценка? |
|---|---|---|
| показывать вакансии с оценки 6, а не 5 | `MIN_SCORE` в [config.py:11](../../job_finder/config.py#L11) | нет |
| поменять цветовые полосы оценки | `score_colors` в [style.py:30](../../job_finder/style.py#L30) | нет |
| сменить цвета темы | `COLORS` в [style.py:5](../../job_finder/style.py#L5) | нет |
| меньше вакансий с Himalayas | `"seniority": "Entry-level"` в `HIMALAYAS_PARAMS` ([config.py:27](../../job_finder/config.py#L27)) | нет |
| поправить правила оценки | `RULES` в [llm.py:28](../../job_finder/llm.py#L28) | **да, всё** |
| другую модель LM Studio | `MODEL` в [config.py:17](../../job_finder/config.py#L17); модель должна быть скачана (`lms get …`) и помещаться в видеопамять | **да, всё** |
| добавить навык для отсева | строку в `## Skills` резюме | **да, всё** (резюме изменилось) |
| вернуть скрытую вакансию | SQL `UPDATE jobs SET hidden = 0 WHERE url = '…'` ([раздел 6](06-db.md#как-заглянуть-в-базу-самому)) | нет |
| переоценить одну вакансию | SQL `UPDATE jobs SET cv_hash = NULL WHERE url = '…'` | только её |

### Добавить новый источник

1. В [sources.py](../../job_finder/sources.py) написать `parse_новый(data) -> list[Job]` — разбор
   ответа в `Job`. Обязательные поля читать через `item["…"]`, необязательные — через
   `item.get("…")`, HTML описания пропускать через `html_to_text`, дату приводить к `YYYY-MM-DD`.
2. Написать `fetch_новый() -> list[Job]`: `_get(URL, параметры)` → `.json()` → `parse_новый`.
   URL и параметры — в [config.py](../../job_finder/config.py).
3. Добавить пару `("Имя", fetch_новый)` в `SOURCES` — на место по приоритету для дублей.
4. В [tests/test_sources.py](../../tests/test_sources.py) — образец ответа и тест на `parse_новый`.

Больше ничего менять не нужно: `worker`, `db` и окно работают с любым источником из `SOURCES`.

### Добавить колонку в таблицу

Название — в `COLUMNS` ([window.py:12](../../job_finder/window.py#L12)), значение — в список
`values` в `render()` ([window.py:248](../../job_finder/window.py#L248)). Если нужного поля нет в
строке — добавить его в `make_row` ([db.py:96](../../job_finder/db.py#L96)).

### Добавить поле в ответ модели

Например, «зарплата»: поле в `SCHEMA` и в `required` ([llm.py:15](../../job_finder/llm.py#L15)),
описание поля в разделе «Ответь JSON-объектом» в `RULES` (это изменит ключ — будет полная
переоценка), вывод в `show_details` ([window.py:268](../../job_finder/window.py#L268)).
Старые оценки в базе нового поля не содержат — поэтому в окне читайте его через
`evaluation.get(...)`.

## Отладка: где искать проблему

### Журнал `job_finder.log`

Всё важное пишется туда. Что можно встретить:

| Запись | Откуда | Значит |
|---|---|---|
| `INFO job_finder.worker: Загружено: {'junior.guru': 48, …}` | [worker.py:59](../../job_finder/worker.py#L59) | сколько вакансий пришло с каждого источника (после удаления дублей) |
| `INFO job_finder.worker: К оценке: 42` | [worker.py:70](../../job_finder/worker.py#L70) | размер очереди после отсева |
| `INFO job_finder.worker: Готово: …` | [worker.py:45](../../job_finder/worker.py#L45) | итог обновления |
| `ERROR job_finder.sources: Источник X не загрузился` + трассировка | [sources.py:164](../../job_finder/sources.py#L164) | источник упал |
| `ERROR job_finder.worker: LM Studio недоступна` + трассировка | [worker.py:81](../../job_finder/worker.py#L81) | `prepare()` упал или модель потеряна |
| `ERROR job_finder.worker: Не удалось оценить <url>` | [worker.py:101](../../job_finder/worker.py#L101) | одна вакансия не оценилась |
| `ERROR job_finder.worker: Обновление упало` | [worker.py:48](../../job_finder/worker.py#L48) | непредвиденная ошибка обновления |
| `ERROR job_finder.llm: Не удалось выгрузить модель` | [llm.py:165](../../job_finder/llm.py#L165) | `lms unload` не сработал |
| `CRITICAL root: Необработанное исключение` | [__main__.py:28](../../job_finder/__main__.py#L28) | ошибка в главном потоке (например, при запуске) |

### Запуск с консолью

```bash
.venv/Scripts/python.exe -m job_finder
```

Из корня проекта. Окно то же самое, но через `python.exe`, а не `pythonw.exe`. Лог по-прежнему
пишется в файл, зато в консоли видны предупреждения самого Qt.

### LM Studio

```bash
~/.lmstudio/bin/lms.exe ps
```

```bash
~/.lmstudio/bin/lms.exe server status
```

```bash
nvidia-smi
```

`lms ps` — какие модели загружены (во время оценки там должна быть `job-finder`, после — пусто),
`server status` — работает ли сервер, `nvidia-smi` — сколько видеопамяти занято.

### «Приложение уже открыто», а окна нет

Значит, жив процесс прошлого запуска (например, завис). Найдите `pythonw.exe` в диспетчере задач
и завершите его. Удалять `job_finder.lock` вручную не нужно.

## Известные ограничения и расхождения

Всё ниже проверено по коду. Это не срочные ошибки, а места, о которых полезно знать.

| # | Что | Где | Последствие |
|---|---|---|---|
| 1 | Без `master_cv.md` таблица пустая, хотя спецификация обещает показывать прежние оценки | [window.py:238](../../job_finder/window.py#L238) | удалили или переименовали резюме — список пропал до его возвращения |
| 2 | Ошибки источников видны только в итоговой строке | [worker.py:60](../../job_finder/worker.py#L60) | во время долгой оценки строка показывает «Оценено N из M», об упавшем источнике узнаете только в конце |
| 3 | Ответ `200` без ключа `jobs` выглядит как пустая выдача | [sources.py:62](../../job_finder/sources.py#L62), [83](../../job_finder/sources.py#L83) | если API Himalayas или Jobicy вдруг вернёт другую структуру, все его вакансии станут неактивными (до следующей нормальной выдачи) |
| 4 | Ошибки запуска — только в логе | [__main__.py:28](../../job_finder/__main__.py#L28) | если, например, `db.init()` упадёт, окно просто не появится |
| 5 | Нет остановки после многих неудачных оценок подряд | [worker.py:100-102](../../job_finder/worker.py#L100-L102) | если сервер зависнет, каждая вакансия будет ждать таймаута 120 с |
| 6 | Тексты ошибок LM Studio не обрезаются | [worker.py:82](../../job_finder/worker.py#L82) | у источников ошибка обрезана до 150 символов, а «LM Studio: …» может быть длинной строкой |
| 7 | Устаревший комментарий у `cv_hash` | [db.py:23](../../job_finder/db.py#L23) | там «SHA-256 master_cv.md», на деле — резюме + модель + правила |
| 8 | Ключ не учитывает `SCHEMA`, `temperature`, длину описания, формат текста вакансии | [llm.py:67](../../job_finder/llm.py#L67) | после их изменения старые оценки остаются действительными |
| 9 | Изменение описания вакансии на сайте не вызывает переоценку | [db.py:55-58](../../job_finder/db.py#L55-L58) | оценка остаётся от старого текста |
| 10 | Дубли убираются только среди загрузившихся источников | [sources.py:166](../../job_finder/sources.py#L166) | если упал junior.guru, его старые вакансии остаются активными, а их копии с Himalayas запишутся как новые — одна вакансия может появиться в таблице дважды |
| 11 | `requirements.txt` разрешает PySide6 6.7, а `setColorScheme` появился в Qt 6.8 | [requirements.txt](../../requirements.txt), [style.py:80](../../job_finder/style.py#L80) | сейчас стоит 6.12, всё работает; на чистой установке с 6.7 запуск упал бы |
| 12 | Отсев ищет навык целым словом | [skills.py:30](../../job_finder/skills.py#L30) | `Python3` не совпадает с `Python` |
| 13 | Скрытую вакансию нельзя вернуть из окна | — | только SQL-запросом |
| 14 | Тесты не покрывают ветки `prepare()` и сообщения `worker` о резюме | [tests/](../../tests/) | см. [раздел 9](09-tests.md#что-тестами-не-покрыто) |

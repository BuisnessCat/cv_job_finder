# 1. Обзор

[← Оглавление](README.md) · [Дальше: установка и запуск →](02-startup-and-config.md)

## Что делает приложение

Это обычное окно Windows (библиотека PySide6 — Qt для Python). При открытии и по кнопке
«Refresh» приложение:

1. **скачивает** свежие вакансии с четырёх сайтов-агрегаторов через их открытые API — только в Праге
   или удалённые;
2. **отсеивает без ИИ** вакансии, где нет ни одного навыка из вашего `master_cv.md`;
3. **оценивает** оставшиеся локальной языковой моделью в LM Studio: насколько реально по этому
   резюме пройти отбор (оценка 1–10 и разбор «YOU HAVE / MISSING / RISKS»);
4. **показывает** вакансии с оценкой ≥ 5, лучшие сверху;
5. **помнит отклики:** кнопкой «I applied» вакансия переносится во вкладку «My applications», где потом
   отмечается итог (приняли / отказали). Перепубликованная вакансия с той же компанией и названием
   помечается «↻ / You already applied». К отклику можно записать заметку; видно, сколько дней ждём
   ответа, а дольше 14 дней — янтарная подсказка напомнить о себе или закрыть отклик;
6. **помечает новые:** вакансии, появившиеся после прошлого закрытия окна, отмечены «•» и жирным,
   на переключателе — сколько их: «Found · 21 (+3)».

Всё сохраняется в базу SQLite, поэтому уже оценённая вакансия второй раз не оценивается —
пока не поменяется резюме, правила оценки или модель.

## Из чего состоит

Код разбит на модули так, что **каждый отвечает ровно за одну вещь**:

| Модуль | Отвечает за | Знает про Qt? | Ходит в сеть / на диск? |
|---|---|---|---|
| [`config.py`](../../job_finder/config.py) | все настройки и пути | нет | нет |
| [`sources.py`](../../job_finder/sources.py) | загрузку вакансий и приведение их к `Job` | нет | сеть (4 API) |
| [`skills.py`](../../job_finder/skills.py) | отсев по навыкам | нет | нет (чистые функции) |
| [`llm.py`](../../job_finder/llm.py) | всё общение с моделью | нет | LM Studio (`lms.exe` + HTTP) |
| [`db.py`](../../job_finder/db.py) | хранение | нет | файл `jobs.db` |
| [`worker.py`](../../job_finder/worker.py) | порядок шагов одного обновления, фоновый поток | только сигналы | через другие модули |
| [`window.py`](../../job_finder/window.py) | окно: таблица, карточка, кнопки | да | через `db` |
| [`cv_window.py`](../../job_finder/cv_window.py) | окно «My CV»: текущий `master_cv.md` | да | читает `master_cv.md` |
| [`style.py`](../../job_finder/style.py) | цвета и стили | только текст стилей | нет |
| [`__main__.py`](../../job_finder/__main__.py) | запуск: лог, блокировка, создание окна | да | лог, блокировка |

Почему так удобно: `sources`, `skills`, `llm`, `db` ничего не знают про окно. Их можно проверять
тестами по отдельности, а заменить модель на другую (например, Claude API) можно, переписав только
`llm.py`.

### Кто кого импортирует

```
__main__ ──► config, db, window
window ────► config, db, llm, style, worker
worker ────► config, db, llm, skills, sources
llm ───────► config, sources (только класс Job)
db ────────► config, sources (только класс Job)
skills ────► sources (только класс Job)
sources ───► config
style ─────► ничего
```

Класс `Job` объявлен в `sources.py` и импортируется оттуда всеми, кому он нужен. Циклических
импортов нет: стрелки идут только «сверху вниз».

### Внешние участники

```
                      ┌──────────────────────────────┐
  junior.guru  ───┐   │                              │
  Himalayas    ───┼──►│     Job Finder               │◄──── master_cv.md (читает)
  Jobicy       ───┤   │     (один процесс pythonw)   │────► jobs.db (читает и пишет)
  Working Nomads ─┘   │                              │────► job_finder.log (пишет)
   HTTP GET           │                              │────► job_finder.lock
                      └──────┬──────────────┬────────┘
                             │ запускает    │ HTTP POST
                             ▼              ▼
                         lms.exe ──► LM Studio (сервер на localhost:1234, модель в видеопамяти)
```

## Сквозной сценарий: от двойного клика до строки в таблице

Это главный раздел обзора: если понять эту цепочку, остальное — детали.

1. **Двойной клик по ярлыку.** Ярлык создан [install.ps1](../../install.ps1#L13-L20) и запускает
   `.venv\Scripts\pythonw.exe -m job_finder` в папке проекта. `pythonw` — Python без окна консоли;
   `-m job_finder` — выполнить пакет `job_finder` как программу, то есть файл `job_finder/__main__.py`.

2. **`main()`** ([__main__.py:22](../../job_finder/__main__.py#L22)):
   включает запись лога в `job_finder.log`, перенаправляет необработанные исключения в лог, задаёт
   иконку и тёмную схему, берёт блокировку `job_finder.lock` (если окно уже открыто — сообщает и
   выходит), вызывает `db.init()` — создаёт таблицу `jobs`, если её ещё нет.

3. **`MainWindow()`** ([window.py:95](../../job_finder/window.py#L95)):
   строит все виджеты, создаёт объект `Worker` и подключает его сигналы к методам окна. Вызывает
   `load_rows()` — в таблице сразу появляются вакансии, оценённые в прошлые запуски.
   `QTimer.singleShot(0, self.refresh)` откладывает запуск обновления до момента, когда окно уже
   будет на экране.

4. **`window.show()` и `app.exec()`** — окно показывается, запускается цикл событий Qt.

5. **Срабатывает таймер → `refresh()`** ([window.py:484](../../job_finder/window.py#L484)):
   кнопка «Refresh» становится неактивной, `worker.start()` запускает **новый фоновый поток**,
   который выполняет `Worker._refresh()`. Окно при этом остаётся отзывчивым.

6. **Загрузка** ([worker.py:55-60](../../job_finder/worker.py#L55-L60)): `sources.fetch_all()` по
   очереди обращается к четырём API, каждый ответ превращается в список `Job`, дубли убираются,
   и для каждого источника вызывается `db.save_jobs()`.

7. **Очередь** ([worker.py:62-69](../../job_finder/worker.py#L62-L69)): читается `master_cv.md`,
   считается ключ оценки, из резюме берётся список навыков. Из базы выбираются вакансии без оценки
   по текущему ключу, из них остаются только те, где нашёлся навык.

8. **Подготовка модели** ([llm.py:94](../../job_finder/llm.py#L94)): если сервер LM Studio не
   запущен — `lms server start`; если модель `job-finder` не загружена — `lms load …`.

9. **Оценка по одной вакансии** ([worker.py:95-106](../../job_finder/worker.py#L95-L106)):
   `llm.evaluate()` отправляет POST-запрос с резюме и текстом вакансии, получает JSON с оценкой,
   `db.save_evaluation()` сразу сохраняет его, а сигнал `evaluated` передаёт строку окну.
   В главном потоке срабатывает `on_evaluated()` — если оценка ≥ 5, строка встаёт в таблицу на своё
   место. Сигнал `progress` обновляет полосу прогресса и надпись «Evaluated N of M».

10. **Завершение** ([worker.py:83-89](../../job_finder/worker.py#L83-L89)): `llm.release()`
    выгружает модель из видеопамяти, в строку состояния уходит итог «Done: X matches out of Y
    evaluated», сигнал `finished` снова включает кнопку «Refresh».

11. **Работа с результатом.** Клик по строке → `on_select()` → `show_details()` заполняет карточку
    справа. «Open job» открывает ссылку в браузере, «Hide» помечает вакансию в базе
    `hidden = 1` и убирает строку.

12. **Закрытие окна** → `closeEvent()` ([window.py:560](../../job_finder/window.py#L560)): несохранённая
    заметка дописывается в базу, оценённые вакансии отмечаются просмотренными; если модель сейчас
    загружена, запускается `lms unload` без ожидания. `app.exec()` возвращает
    управление, и `os._exit()` сразу завершает процесс, не дожидаясь фонового потока.

### То же самое по потокам

```
 Главный поток (окно)                 Фоновый поток (Worker)               Внешний мир
 ────────────────────                 ──────────────────────               ───────────
 refresh() ── worker.start() ───────► _run() → _refresh()
 status_label.setText ◄────────────── status("Loading jobs…")
                                      sources.fetch_all() ────────────────► 4 API (HTTP GET)
                                      db.save_jobs() × 4 ─────────────────► jobs.db
                                      read_cv(), load_skills(),
                                      pending_jobs(), matches()
 status_label.setText ◄────────────── status("Starting LM Studio…")
                                      llm.prepare() ──────────────────────► lms.exe → LM Studio
                                      ┌ для каждой вакансии:
                                      │ llm.evaluate() ───────────────────► POST /v1/chat/completions
                                      │ db.save_evaluation() ─────────────► jobs.db
 on_evaluated(row) ◄───────────────── │ evaluated.emit(row)
 on_progress(done, total) ◄────────── │ progress.emit(done, total)
                                      └
                                      llm.release() ──────────────────────► lms unload
 status_label.setText ◄────────────── status("Done: …")
 on_finished() ◄───────────────────── finished.emit()
```

Стрелки справа налево — это сигналы Qt. Они пересекают границу потоков безопасно: Qt кладёт вызов
в очередь главного потока, и методы окна всегда выполняются в главном потоке
(подробно — в разделе [«Фоновое обновление»](07-worker.md#справка-сигналы-qt-и-потоки)).

## Жизненный цикл одной вакансии

```
        появилась на сайте
               │ загрузка (sources) + запись (db.save_jobs)
               ▼
   в базе: active=1, hidden=0, score=NULL
               │
               ├── нет ни одного навыка из резюме ──► лежит в базе, не оценивается и не показывается
               │                                      (проверяется заново при каждом обновлении)
               │ есть навык
               ▼
     в очереди на оценку (db.pending_jobs)
               │ llm.evaluate → db.save_evaluation
               ▼
   оценена: score, evaluation (JSON), cv_hash = текущий ключ
               │
               ├── score < 5 ──► не показывается
               │
               └── score ≥ 5 ──► в найденных ──«Hide»──► hidden=1: больше не показывается
                                    │                    и не оценивается (в окне не вернуть)
                                    └──«I applied»──► отклик: status, applied_at; во вкладке «My applications»
                                                      навсегда, не оценивается заново; итог — «Accepted» /
                                                      «Rejected»; «Back to found» — обратно

 В любой момент:
 • пропала из выдачи своего источника   ──► active=0, не показывается; появится снова — active=1
 • изменились резюме, правила или модель ──► ключ не совпадает ──► снова в очереди на оценку
                                            (кроме откликов: они не переоцениваются)
 • впервые записана в базу              ──► seen=0: «•» в таблице до закрытия окна
 • окно закрыли                          ──► все оценённые вакансии seen=1 (просмотрены)
```

## Четыре идеи, на которых держится код

1. **Один тип данных для всех источников.** Каждый сайт отдаёт данные по-своему (CSV, разные
   названия полей, разные форматы дат), но после разбора всё превращается в одинаковый `Job`.
   Дальше по коду никто не знает, откуда пришла вакансия.

2. **Ключ оценки вместо удаления старых оценок.** Оценка хранится вместе с ключом, из которого она
   получена (резюме + модель + правила). Чтобы «сбросить» оценки после правки резюме, ничего не
   надо удалять: запросы просто ищут оценки с *текущим* ключом. Если вернуть резюме как было —
   старые оценки снова станут действительными. Подробно — в [разделе 7](07-worker.md#read_cv-и-ключ-оценки).

3. **Тяжёлая работа — в фоновом потоке, окно получает только готовые результаты.** Фоновый поток
   никогда не трогает виджеты напрямую; он только испускает сигналы.

4. **Модель — только в `llm.py`.** Три функции: `prepare()`, `evaluate()`, `release()`.
   Остальной код не знает, что такое LM Studio.

## Цифры (замерено 2026-10-13)

- Модель `mistralai/ministral-3-8b` на RTX 3060 12 ГБ: около 8–9 секунд на вакансию.
- Полная оценка ~259 вакансий: около 37 минут. Столько же займёт полная переоценка после любой
  правки резюме, правил или модели.
- После переписывания правил оценки подходящими (≥ 5) оказались 23 из 259.

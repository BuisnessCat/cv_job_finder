# 4. Отсев по навыкам — skills.py

[← Источники](03-sources.md) · [Оглавление](README.md) · [Дальше: оценка моделью →](05-llm.md)

Файл: [job_finder/skills.py](../../job_finder/skills.py) (30 строк, две функции).

## Зачем

Модель тратит 8–9 секунд на вакансию. Многие вакансии из выдачи заведомо не подходят: в них нет
ни Python, ни SQL, ни чего-то ещё из резюме (например, вакансия Java-разработчика или дизайнера).
Простая проверка регулярным выражением занимает микросекунды и убирает такие вакансии **до** модели.

Проверка нарочно мягкая: достаточно **одного** совпавшего навыка. Её цель — выбросить совсем
чужое, а не решать, подходит ли вакансия; это делает модель.

## `load_skills(cv_text)` — [строка 7](../../job_finder/skills.py#L7)

Достаёт список навыков из раздела `## Skills` резюме.

### Каким должен быть раздел в master_cv.md

```markdown
## Skills — level and evidence
- Python — main language
- SQL — JOINs
- SQLAlchemy 2.0 ORM — models
- Git, GitHub — version control
- requests, BeautifulSoup — web scraping
- Concepts — OOP, REST API design
- In progress, NOT to be presented as done: pytest, Docker Compose

## Projects
...
```

Из такого раздела получится `["Python", "SQL", "SQLAlchemy", "Git", "GitHub", "requests", "BeautifulSoup"]`
(пример взят из [tests/test_skills.py](../../tests/test_skills.py#L4-L22)).

### Алгоритм по строкам

Функция идёт по строкам резюме и помнит одно состояние — `in_skills` («мы сейчас внутри раздела
Skills?»).

```python
for line in cv_text.splitlines():
    if line.startswith("## "):                       # любой заголовок 2-го уровня
        in_skills = line.startswith("## Skills")     # вошли в Skills или вышли из него
        continue
    if not in_skills or not line.startswith("- "):   # не тот раздел или не пункт списка
        continue
    item = line[2:]                                  # строка без «- »
    if item.startswith(("Concepts", "In progress")): # эти строки пропускаем
        continue
    for part in item.split(" — ")[0].split(","):     # до тире, по запятым
        words = part.split()
        if words:
            skills.append(words[0])                  # первое слово каждого элемента
```

Разбор строки `- SQLAlchemy 2.0 ORM — models`:

```
item                 = "SQLAlchemy 2.0 ORM — models"
.split(" — ")[0]     = "SQLAlchemy 2.0 ORM"
.split(",")          = ["SQLAlchemy 2.0 ORM"]
первое слово         = "SQLAlchemy"
```

Разбор строки `- Git, GitHub — version control`: до тире `"Git, GitHub"` → по запятым
`["Git", " GitHub"]` → первые слова `"Git"`, `"GitHub"`.

### Тонкости

- **Заголовок может продолжаться**: `## Skills — level and evidence` подходит, потому что проверка —
  `startswith("## Skills")`.
- **Раздел заканчивается** на следующем `## `. Заголовки `### ` раздел не заканчивают
  (`"### X".startswith("## ")` — ложь, третий символ `#`, а не пробел), но и навыков не дают —
  это не пункты списка.
- **Только пункты `- `** (дефис и пробел) в начале строки. Пункты `* ` и вложенные пункты с отступом
  (`  - …`) не учитываются.
- **Разделитель — длинное тире с пробелами** ` — `. Если написать обычный дефис
  (`- Docker - basics`), тире не найдётся, и вся строка уйдёт в разбор по запятым: навыком станет
  первое слово каждого куска, что может дать лишние «навыки».
- **`Concepts` и `In progress`** пропускаются: понятия вроде OOP и то, что ещё изучается, не должны
  пропускать вакансии.
- `splitlines()` понимает и `\n`, и `\r\n` (файлы из Windows). BOM в начале файла попадает только
  в первую строку (`# Master CV`) и ничего не ломает — это проверяет тест.
- Если раздела нет или он пустой — возвращается `[]`, и `worker` сообщает «No Skills section in
  master_cv.md, evaluation skipped».

## `matches(job, skills)` — [строка 27](../../job_finder/skills.py#L27)

```python
text = f"{job.title}\n{job.description}"
return any(re.search(rf"(?<!\w){re.escape(skill)}(?!\w)", text, re.IGNORECASE) for skill in skills)
```

Ищет каждый навык в названии и описании вакансии **как целое слово, без учёта регистра**.
`any(...)` возвращает `True` на первом найденном навыке и дальше не ищет.

### Разбор регулярного выражения

Для навыка `SQL` получается шаблон `(?<!\w)SQL(?!\w)`:

| Часть | Значит |
|---|---|
| `(?<!\w)` | *negative lookbehind*: **перед** совпадением нет буквы, цифры или `_` |
| `SQL` | сам навык; `re.escape` экранирует спецсимволы (`.`, `+`, `#`…), чтобы `Node.js` или `C++` искались буквально |
| `(?!\w)` | *negative lookahead*: **после** совпадения нет буквы, цифры или `_` |
| `re.IGNORECASE` | регистр не важен |
| `rf"..."` | r — «сырая» строка (обратные слеши не экранируются), f — подстановка `{...}` |

Почему не привычное `\bSQL\b`: `\b` — «граница слова» — работает только рядом с буквами и цифрами.
Для навыка, который кончается на символ (`C++`, `C#`), `\b` после него требовал бы букву следом и
искал бы не то. Пара lookbehind/lookahead означает ровно «по краям нет символов слова».

### Примеры

| Навык | Текст | Совпало? | Почему |
|---|---|---|---|
| `Python` | `Junior PYTHON developer` | да | регистр не важен |
| `SQL` | `Znalost T-SQL` | да | `-` не символ слова |
| `SQL` | `MySQL` | нет | перед `SQL` буква `y` |
| `Git` | `GitLab CI` | нет | после `Git` буква `L` |
| `Python` | `Python3` | нет | после `Python` цифра `3` |

Последний пример показывает цену строгости: если бы в вакансии было только `Python3`, она бы не
прошла. На практике в описании почти всегда есть и просто «Python».

## Где используется

Только в [worker.py:66-69](../../job_finder/worker.py#L66-L69):

```python
skill_list = skills.load_skills(cv_text)
...
todo = [job for job in db.pending_jobs(cv_hash) if skills.matches(job, skill_list)]
```

Отсев применяется **к очереди на оценку**, а не при записи в базу. Поэтому:

- вакансии, не прошедшие отсев, всё равно лежат в базе (с `score = NULL`) и проверяются заново
  при каждом обновлении — это дёшево;
- если вы добавите навык в резюме, такие вакансии сами попадут в очередь при следующем обновлении
  (а поскольку резюме изменилось, переоценятся и все остальные).

# 6. База данных — db.py

[← Оценка моделью](05-llm.md) · [Оглавление](README.md) · [Дальше: фоновое обновление →](07-worker.md)

Файл: [job_finder/db.py](../../job_finder/db.py) (112 строк).

Почему **SQLite**: вся база — один файл `jobs.db`, модуль `sqlite3` встроен в Python, не нужен
сервер (в отличие от PostgreSQL). Для одного пользователя и нескольких сотен вакансий — то, что надо.

## Таблица `jobs` — [строка 11](../../job_finder/db.py#L11)

Одна таблица, одна строка = одна вакансия.

| Колонка | Тип | Кто пишет | Смысл |
|---|---|---|---|
| `url` | TEXT, **PRIMARY KEY** | `save_jobs` | ссылка на вакансию — уникальный ключ |
| `source` | TEXT | `save_jobs` | имя источника |
| `title` | TEXT | `save_jobs` | название |
| `company` | TEXT | `save_jobs` | компания |
| `city` | TEXT | `save_jobs` | город или «Удалённо…» |
| `published` | TEXT | `save_jobs` | дата `YYYY-MM-DD` (строкой) |
| `description` | TEXT | `save_jobs` | описание, обычный текст |
| `active` | INTEGER, по умолчанию 1 | `save_jobs` | 1 — есть в последней выдаче источника; 0 — пропала |
| `hidden` | INTEGER, по умолчанию 0 | `hide` | 1 — пользователь нажал «Скрыть» |
| `score` | INTEGER, может быть NULL | `save_evaluation` | оценка 1–10; NULL — ещё не оценена |
| `evaluation` | TEXT, может быть NULL | `save_evaluation` | весь ответ модели как JSON-строка |
| `cv_hash` | TEXT, может быть NULL | `save_evaluation` | **ключ оценки**, с которым получена эта оценка |

Первые семь колонок совпадают с полями `Job` **в том же порядке** — на этом построено чтение в
`list_jobs` (см. ниже). Остальные семь — состояние вакансии в нашем приложении.

Про `cv_hash` ([строка 24](../../job_finder/db.py#L24)): это ключ оценки — SHA-256 от резюме
**вместе с моделью и правилами оценки** (см. [read_cv](07-worker.md#read_cv-и-ключ-оценки)).

Про отклики ([строки 25-26](../../job_finder/db.py#L25-L26)): `status` — `NULL` (отклика нет),
`'applied'` (ждём ответа), `'accepted'` (приняли) или `'rejected'` (отказали); список допустимых
значений — `STATUSES` ([строка 33](../../job_finder/db.py#L33)). `applied_at` — дата отклика
`ГГГГ-ММ-ДД`.

`JOB_FIELDS` ([строка 31](../../job_finder/db.py#L31)) — строка `"url, source, title, company, city,
published, description"`, чтобы не повторять список колонок в каждом запросе.

## Соединение `_connect()` — [строка 36](../../job_finder/db.py#L36)

```python
@contextmanager
def _connect():
    conn = sqlite3.connect(config.DB_PATH)
    conn.row_factory = sqlite3.Row
    try:
        with conn:          # транзакция: коммит или откат
            yield conn
    finally:
        conn.close()
```

Используется так: `with _connect() as conn: conn.execute(...)`.

> **Справка: `@contextmanager`.** Превращает функцию-генератор в объект для `with`.
> Код до `yield` выполняется при входе в `with`, значение `yield` попадает в `as conn`,
> код после — при выходе (даже если внутри было исключение — благодаря `try/finally`).

Три важные вещи:

1. **Новое короткое соединение на каждый вызов.** Базой пользуются два потока: окно (чтение
   в `load_rows`, `hide`) и фоновый `Worker` (всё остальное). Объект соединения `sqlite3` по
   умолчанию нельзя использовать из другого потока, чем тот, где он создан (будет
   `ProgrammingError`). Своё соединение на каждый вызов эту проблему снимает. Открыть файл SQLite —
   очень дёшево.
2. **`with conn:` — транзакция.** Если блок прошёл без ошибки — `COMMIT`, если было исключение —
   `ROLLBACK`. Внимание: `with conn` в `sqlite3` **не закрывает** соединение, поэтому отдельно
   `conn.close()` в `finally`.
3. **`row_factory = sqlite3.Row`.** Строки результата можно читать и по имени колонки
   (`row["evaluation"]`), и по номеру, и превращать в словарь `dict(row)`.

Если два потока пишут одновременно, SQLite сам ставит второго в очередь (по умолчанию ждёт до 5 с).
Наши транзакции короткие, так что ожидания незаметны.

## `init()` — [строка 48](../../job_finder/db.py#L48)

`CREATE TABLE IF NOT EXISTS` — создать таблицу, если её нет. Вызывается один раз при старте из
`__main__`.

Если `jobs.db` создана до появления откликов, в ней нет колонок `status` и `applied_at`.
`init()` смотрит список колонок (`PRAGMA table_info(jobs)`, [строка 52](../../job_finder/db.py#L52))
и добавляет недостающие через `ALTER TABLE jobs ADD COLUMN … TEXT`. Вакансии и оценки при этом
сохраняются, у старых строк новые колонки просто пустые (`NULL` — отклика нет). Других миграций
нет: если поменять `SCHEMA` иначе, существующий `jobs.db` сам не изменится.

## `save_jobs(source, jobs)` — [строка 58](../../job_finder/db.py#L58)

Записывает свежую выдачу одного источника. Два шага **в одной транзакции**:

```sql
-- 1. Все вакансии этого источника — неактивные
UPDATE jobs SET active = 0 WHERE source = ?;

-- 2. Для каждой вакансии из выдачи — вставить или обновить (upsert)
INSERT INTO jobs (url, source, title, company, city, published, description)
VALUES (:url, :source, :title, :company, :city, :published, :description)
ON CONFLICT(url) DO UPDATE SET
    source = excluded.source, title = excluded.title, company = excluded.company,
    city = excluded.city, published = excluded.published,
    description = excluded.description, active = 1;
```

> **Справка: upsert.** `INSERT … ON CONFLICT(url) DO UPDATE` — «вставь, а если строка с таким `url`
> уже есть, обнови её». `excluded` — это строка, которую мы *пытались* вставить.
> `:url`, `:source`… — именованные параметры; значения берутся из словаря `asdict(job)`.
> `executemany` выполняет запрос для каждого словаря из списка.

Итог:

- вакансии, которые есть в выдаче, — обновлены и `active = 1`;
- вакансии этого источника, которых в выдаче нет, — остались с `active = 0` после шага 1;
- **не трогаются** `hidden`, `score`, `evaluation`, `cv_hash` — их нет в `DO UPDATE SET`. Поэтому
  повторная загрузка не сбрасывает оценку и не «раскрывает» скрытую вакансию;
- раз всё в одной транзакции, окно никогда не увидит момент, когда шаг 1 уже сделан, а шаг 2 ещё нет.

Пример:

```
было в базе (Jobicy):  a (active=1, score=7)   b (active=1, hidden=1)   c (active=1)
пришло от Jobicy:      a, b, d
стало:                 a (active=1, score=7)   b (active=1, hidden=1)   c (active=0)   d (active=1, score=NULL)
```

Следствие: если описание вакансии на сайте поменялось, текст в базе обновится, а оценка останется
прежней — ключ оценки от описания не зависит.

## `pending_jobs(cv_hash)` — [строка 73](../../job_finder/db.py#L73)

Очередь на оценку:

```sql
SELECT url, source, title, company, city, published, description FROM jobs
WHERE active = 1 AND hidden = 0 AND (cv_hash IS NULL OR cv_hash != ?)
ORDER BY published DESC
```

- Активные, не скрытые, и **либо без оценки, либо оценённые с другим ключом**.
- Почему отдельно `cv_hash IS NULL`: в SQL сравнение с NULL даёт не «истину», а NULL
  (`NULL != 'abc'` — это NULL), и `WHERE` такую строку отбросил бы. Поэтому NULL проверяется явно.
- `ORDER BY published DESC` — сначала новые. Сортировка строк `YYYY-MM-DD` совпадает с сортировкой
  дат. Пустая дата `''` при убывании оказывается в конце.
- `Job(**dict(row))` — строка → словарь → `Job` по именам полей.

## `save_evaluation(url, evaluation, cv_hash)` — [строка 85](../../job_finder/db.py#L85)

```sql
UPDATE jobs SET score = ?, evaluation = ?, cv_hash = ? WHERE url = ?
```

`score` копируется в отдельную колонку, чтобы по нему фильтровать и сортировать в SQL. Весь ответ
модели хранится в `evaluation` как JSON; `ensure_ascii=False` оставляет русские буквы читаемыми
(иначе было бы `По…`).

## Отклики — `apply`, `set_status`, `unapply` — [строки 98-114](../../job_finder/db.py#L98-L114)

| Функция | Что делает |
|---|---|
| `apply(url)` | «Подался»: `status = 'applied'`, `applied_at` = сегодня (`date.today()`) |
| `set_status(url, status)` | итог отклика — одно из `STATUSES`; дата отклика не меняется |
| `unapply(url)` | «Вернуть в найденные»: `status` и `applied_at` → `NULL` |

Вакансия с откликом не попадает ни в найденные (`list_jobs`), ни в очередь на оценку
(`pending_jobs`), ни в счётчик `count_evaluated` — во всех трёх запросах стоит `status IS NULL`.
Поэтому после правки резюме отклики заново не оцениваются.

## `count_evaluated(cv_hash)` — [строка 117](../../job_finder/db.py#L117)

Сколько активных нескрытых вакансий оценено с текущим ключом — для итога «Готово: X подходящих
из **Y** оценённых». `fetchone()[0]` — первая колонка первой строки, то есть само число.

## `make_row(job, evaluation)` — [строка 126](../../job_finder/db.py#L126)

Готовит словарь «строка таблицы» для окна. Так выглядит каждая строка, которую видит `window.py`:

```python
{
    "url": "https://…", "source": "Jobicy", "title": "Junior Python Developer",
    "company": "ACME", "city": "Praha", "published": "2026-10-12",
    "score": 7,
    "evaluation": {"score": 7, "summary": "…", "have": [...], "missing": [...], "risks": [...]},
}
```

Описание (`description`) удаляется: окну оно не нужно, а держать в памяти сотни длинных текстов
незачем. `{**row, "score": …}` — новый словарь: все поля `row` плюс два новых.

`make_row` вызывается из двух мест: `list_jobs` (чтение из базы) и `worker._evaluate` (свежая
оценка) — поэтому строки в окне всегда одной формы, откуда бы ни пришли.

## `list_jobs(cv_hash, min_score)` — [строка 133](../../job_finder/db.py#L133)

Что показывать в окне:

```sql
SELECT url, source, title, company, city, published, description, evaluation FROM jobs
WHERE active = 1 AND hidden = 0 AND cv_hash = ? AND score >= ?
ORDER BY score DESC, published DESC
```

Лучшие сверху, при равной оценке — новые сверху.

Строка 112 — самая хитрая в модуле:

```python
make_row(Job(*tuple(row)[:7]), json.loads(row["evaluation"]))
```

- `tuple(row)[:7]` — первые 7 значений строки (`url … description`, порядок как в `JOB_FIELDS`);
- `Job(*…)` — передать их в `Job` **по позиции**. Работает, потому что порядок колонок в
  `JOB_FIELDS` совпадает с порядком полей в `Job` (об этом комментарий на [строке 30](../../job_finder/db.py#L30));
- `json.loads(row["evaluation"])` — JSON-строку обратно в словарь.

## Как заглянуть в базу самому

Закрывать приложение не обязательно, но окно увидит ваши изменения только после «Обновить».
Удобнее всего — расширение для VS Code вроде «SQLite Viewer» или программа DB Browser for SQLite.
Можно и из терминала, Python уже есть в `.venv` (запускать из корня проекта):

```bash
.venv/Scripts/python.exe -c "import sqlite3; c = sqlite3.connect('jobs.db'); [print(r) for r in c.execute('SELECT source, active, COUNT(*) FROM jobs GROUP BY source, active')]"
```

Полезные запросы:

```sql
-- Сколько вакансий у каждого источника, активных и нет
SELECT source, active, COUNT(*) FROM jobs GROUP BY source, active;

-- Распределение оценок
SELECT score, COUNT(*) FROM jobs WHERE active = 1 AND hidden = 0 GROUP BY score ORDER BY score DESC;

-- Лучшие вакансии с разбором
SELECT score, title, company, evaluation FROM jobs
WHERE active = 1 AND hidden = 0 AND score IS NOT NULL ORDER BY score DESC LIMIT 10;

-- Активные вакансии без оценки (обычно — не прошли отсев по навыкам)
SELECT title, company, source FROM jobs WHERE active = 1 AND hidden = 0 AND score IS NULL;

-- Скрытые вакансии
SELECT url, title, company FROM jobs WHERE hidden = 1;

-- Вернуть скрытую вакансию
UPDATE jobs SET hidden = 0 WHERE url = 'https://…';

-- Переоценить одну вакансию при следующем обновлении
UPDATE jobs SET cv_hash = NULL WHERE url = 'https://…';
```

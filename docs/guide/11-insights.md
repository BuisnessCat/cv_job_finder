# 11. Вкладка Insights — `insights.py` и её часть в окне

Вкладка отвечает на два вопроса: **чего мне чаще всего не хватает** и **что вообще чаще всего
требуют**. Считается по разборам модели всех оценённых вакансий — модель для этого не вызывается.
Спецификация — раздел 13 спека.

```
db.evaluations(ключ)           все разборы: [{"have": [...], "missing": [...], ...}, ...]
skills.skill_lines(резюме)     строки раздела Skills без Concepts / In progress
        │                                │
        └──────────► insights.analyze ◄──┘
                          │  find() сводит каждую фразу к названиям из REQUIREMENTS
                          ▼
                 Insights(total, missing, required, in_cv, unknown)
                          │
                          ▼
             window.render_insights → две карточки полос + строка внизу
```

## Зачем словарь

Модель пишет требования свободным текстом, и почти каждая фраза уникальна: из 1031 пункта
«не хватает» разных формулировок было 1008 («cloud platforms (aws/gcp/azure)», «cloud platform
knowledge», …). Посчитать «как есть» нельзя — сначала фразы сводятся к общим названиям.

## `REQUIREMENTS` — [строка 9](../../job_finder/insights.py#L9)

Словарь «название → варианты написания». Варианты — регулярные выражения:

```python
"Kubernetes": [r"kubernetes", r"k8s", r"helm", r"openshift"],
"C#/.NET": [r"c#", r"\.net", r"asp\.net", r"dotnet"],
"Experience 2+ years": [r"(?:[2-9]|1\d)\+?\s*(?:years?|yrs)", r"senior", ...],
```

Группы: языки, фреймворки, данные, инфраструктура, AI, практики и нетехнические требования (опыт,
языки, диплом, предметная область). Порядок в словаре ни на что не влияет.

`TOP = 20` ([строка 6](../../job_finder/insights.py#L6)) — сколько строк показывать в каждом списке.

## Как ищется совпадение — `_PATTERNS`, [строка 111](../../job_finder/insights.py#L111)

Все варианты требования склеиваются в одно выражение:

```python
(?<![\w#+.])(?:вариант1|вариант2|...)(?![\w#+])
```

- `(?<![\w#+.])` — перед совпадением нет буквы, цифры, `#`, `+` или точки;
- `(?![\w#+])` — после него нет буквы, цифры, `#` или `+`.

Поэтому `C` не находится внутри `C#` (после `c` стоит `#`), `Java` не находится внутри
`JavaScript`, а `.NET` и `C++` находятся целиком. Регистр не важен (`re.IGNORECASE`).

Короткие варианты, похожие на обычные слова, сужены:

| Вариант | Почему так |
|---|---|
| `go(?!-)` | «go-to-market» — не язык Go |
| `r(?=\s*[,/)])` | R — только перед запятой, `/` или `)`: «R, SQL», «R/Python»; «R&D» не подходит |
| `master'?s degree` | «Scrum Master» — не диплом |
| `(?<!a/b )(?<!penetration )testing` | «A/B testing» — аналитика, «penetration testing» — безопасность |

Одна фраза может дать несколько требований: «cloud platforms (AWS/GCP/Azure)» → Cloud (any), AWS,
GCP, Azure.

## `find(text)` — [строка 115](../../job_finder/insights.py#L115)

Возвращает множество названий требований, найденных в тексте. Пустое множество — фраза не
распознана.

## `Insights` — [строка 121](../../job_finder/insights.py#L121)

Результат подсчёта:

| Поле | Что это |
|---|---|
| `total` | сколько вакансий посчитано |
| `missing` | `[(требование, вакансий), …]` — где модель записала его в «Missing», без навыков из резюме |
| `required` | `[(требование, вакансий, из них засчитано вам), …]` — где оно есть в «You have» или «Missing» |
| `in_cv` | требования, найденные в строках раздела Skills |
| `unknown` | сколько пунктов «Missing» не совпало ни с одним требованием |

## `analyze(evaluations, cv_skill_lines)` — [строка 134](../../job_finder/insights.py#L134)

1. `in_cv` — требования из строк Skills (`skills.skill_lines`, раздел 4).
2. Для каждой вакансии собираются **множества**: `lacking` — требования из её «Missing», `having` —
   из «You have». Множество — поэтому вакансия даёт требованию не больше одного очка, даже если
   «AWS» и «AWS Lambda» стоят в одном списке.
3. `missing` получает `lacking - in_cv`: если навык уже в резюме, а модель пишет «commercial Python
   experience», — это нехватка опыта, а не пробел, и в список «чего не хватает» он не идёт.
4. `required` получает `lacking | having`, `yours` — `having`. Если требование есть в обоих списках
   одной вакансии, в `required` всё равно одно очко, а «засчитано» не превышает «требуют».
5. Отсутствующие `have` / `missing` считаются пустыми (`evaluation.get(...) or []`).
6. `_top` ([строка 129](../../job_finder/insights.py#L129)) сортирует по убыванию числа, при равенстве —
   по названию, и берёт первые 20.

## Откуда берутся разборы — `db.evaluations`, [db.py:151](../../job_finder/db.py#L151)

Та же выборка, что в итоге «Done: … out of N evaluated» (`count_evaluated`): активные, нескрытые,
без отклика, оценённые по текущему ключу. Если резюме поменялось и идёт переоценка, вкладка считает
по уже переоценённым — цифры растут по ходу.

## Вкладка в окне

- **Переключатель** — третья кнопка `insights_tab`, стиль `segmentMiddle` у средней кнопки
  ([style.py:57](../../job_finder/style.py#L57)).
- **`views`** ([window.py:194](../../job_finder/window.py#L194)) — `QStackedWidget`: 0 — список и
  карточка, 1 — страница Insights. `show_tab(2)` ([window.py:516](../../job_finder/window.py#L516))
  пересчитывает вкладку и показывает её; `show_tab(0 / 1)` возвращает список и карточку.
- **`_build_insights`** ([window.py:367](../../job_finder/window.py#L367)) — две карточки
  («MOST OFTEN MISSING» и «MOST OFTEN REQUIRED») со своими `QVBoxLayout` строк, надпись для пустых
  случаев и строка внизу.
- **`render_insights`** ([window.py:486](../../job_finder/window.py#L486)) — читает резюме и разборы,
  при их отсутствии показывает «No master_cv.md — nothing to analyse» или «Nothing evaluated yet»,
  иначе перерисовывает строки и пишет «Based on N evaluated jobs · U missing items not recognised».
- **`_bar_row`** ([window.py:94](../../job_finder/window.py#L94)) — одна строка: название (у
  навыков из резюме — «✓» и зелёный), полоса и число. Полоса — `QFrame` длиной
  `BAR_WIDTH × число / максимум` ([`BAR_WIDTH`](../../job_finder/window.py#L22) = 220 px) из двух
  частей: зелёная — засчитано вам, красная — не хватает. В списке «Missing» вся полоса красная.
- **Пересчёт** — при каждом открытии вкладки и в `on_finished`
  ([window.py:619](../../job_finder/window.py#L619)), если вкладка открыта. Во время оценки вкладка
  не обновляется на каждую вакансию — только в конце.

## Как пополнить словарь

Внизу вкладки видно, сколько пунктов «Missing» не распознано. Чтобы посмотреть сами фразы, можно
прогнать по базе небольшой скрипт: собрать все `missing` из `db.evaluations(ключ)` и вывести те, для
которых `insights.find(фраза)` пустое. Частые темы добавляются в `REQUIREMENTS` новой строкой или
новым вариантом у существующего требования. После правки — тесты `tests/test_insights.py`: они ловят,
если новый вариант начал совпадать с обычными словами. Модель и ключ оценки словарь не затрагивает —
переоценка не нужна.

# 3. Источники вакансий — sources.py

[← Установка и запуск](02-startup-and-config.md) · [Оглавление](README.md) · [Дальше: отсев по навыкам →](04-skills.md)

Файл: [job_finder/sources.py](../../job_finder/sources.py) (158 строк).

Задача модуля: сходить на четыре сайта, получить вакансии в их собственных форматах и превратить
всё в список одинаковых объектов `Job`. Остальной код про форматы сайтов ничего не знает.

## Устройство модуля в двух слоях

```
fetch_all()                              ← вызывает worker
  ├─ fetch_juniorguru()  ─► _get() ─► parse_juniorguru(text)  ─┐
  ├─ fetch_himalayas()   ─► _get() ─► parse_himalayas(data)   ─┤
  ├─ fetch_jobicy()      ─► _get() ─► parse_jobicy(data)      ─┼─► list[Job] по источникам
  ├─ fetch_workingnomads()─► _get() ─► parse_workingnomads(data)┘
  └─ dedupe()  ─► убрать повторы между всеми источниками
```

- **`parse_*`** — чистые функции: на входе уже полученный текст или JSON, на выходе `list[Job]`.
  В сеть не ходят, поэтому их легко тестировать на сохранённых образцах ответов.
- **`fetch_*`** — делают HTTP-запрос и передают ответ в свой `parse_*`.

## Класс `Job` — [строка 19](../../job_finder/sources.py#L19)

```python
@dataclass
class Job:
    url: str          # ссылка на вакансию — она же уникальный ключ в базе
    source: str       # "junior.guru", "Himalayas", "Jobicy", "Working Nomads"
    title: str
    company: str
    city: str         # город или «Remote…»
    published: str    # YYYY-MM-DD
    description: str  # обычный текст без HTML
```

> **Справка: `@dataclass`.** Декоратор сам пишет за нас `__init__` (конструктор с этими полями),
> `__repr__` (красивый вывод) и `__eq__` (два `Job` равны, если равны все поля — этим пользуются
> тесты: `assert jobs[0] == Job(...)`). Функция `dataclasses.asdict(job)` превращает объект в
> словарь — так `db.py` передаёт поля в SQL.

### `__post_init__` — [строка 29](../../job_finder/sources.py#L29)

Вызывается сразу после `__init__`. Проходит по всем полям (`dataclasses.fields(self)`) и заменяет
`None` на пустую строку. Зачем: в ответах API иногда приходит `null` (например, нет названия
компании). Без замены одна такая запись уронила бы:

- удаление дублей — `_norm(None)` упал бы на `None.lower()`;
- запись в базу — у колонок стоит `NOT NULL`.

## `html_to_text(html)` — [строка 36](../../job_finder/sources.py#L36)

```python
BeautifulSoup(html or "", "html.parser").get_text("\n", strip=True)
```

- `html or ""` — если пришёл `None`, разбираем пустую строку.
- `"html.parser"` — встроенный в Python разборщик HTML (не нужно ставить `lxml`).
- `get_text("\n", strip=True)` — весь текст без тегов; каждый кусок текста обрезается по краям
  и ставится на отдельную строку. Сущности вроде `&amp;` превращаются в `&`.

Пример из теста: `<p>Hledáme <b>Python</b> vývojáře</p>` → `"Hledáme\nPython\nvývojáře"`.
Слова, разделённые тегами, оказываются на разных строках — для модели и для поиска навыков это
не важно.

## Четыре источника

Общая таблица: откуда какое поле берётся.

| Поле `Job` | junior.guru (CSV) | Himalayas (JSON) | Jobicy (JSON) | Working Nomads (JSON) |
|---|---|---|---|---|
| `url` | `url` | `guid` (страница на himalayas.app) | `url` | `url` |
| `title` | `title` | `title` | `jobTitle` | `title` |
| `company` | `company_name` | `companyName` | `companyName` | `company_name` |
| `city` | «Prague», если среди регионов мест есть «Praha»; иначе «Remote», если `remote == "True"` | «Remote» + до 3 стран из `locationRestrictions` | «Remote: » + `jobGeo` | «Remote: » + `location` |
| `published` | первые 10 символов `first_seen_at` | `pubDate` (секунды Unix) → дата UTC | первые 10 символов `pubDate` | первые 10 символов `pub_date` |
| `description` | `description_html` → текст | `description` → текст | `jobDescription` → текст | `description` → текст |
| Отбор | только Прага или удалёнка | — | — | только `category_name == "Development"` |

Почему «первые 10 символов»: даты приходят в формате ISO, например `2026-10-13T02:48:27+00:00`,
и первые 10 символов — это `2026-10-13`. Формат `ГГГГ-ММ-ДД` удобен тем, что такие строки
сортируются так же, как даты, — на этом построена сортировка в базе.

### junior.guru — [parse 40](../../job_finder/sources.py#L40), [fetch 105](../../job_finder/sources.py#L105)

- Чешский сайт для начинающих, ~50 вакансий, отдаёт **CSV-файл**.
- **Только Прага или удалёнка** ([строки 45-51](../../job_finder/sources.py#L45-L51)): у каждой
  вакансии до 20 мест в колонках `locations_N_name` и `locations_N_region`. Если среди регионов есть
  «Praha», город — «Prague» (даже если Прага не первая в списке); иначе, если `remote == "True"`, —
  «Remote»; остальные вакансии пропускаются и в базу не попадают. Проверяется именно регион: у
  пражского района, например «Háje», название без слова «Praha». Сейчас из ~50 остаётся ~20.
  Остальные три источника отдают только удалёнку, им такой отбор не нужен.
- `csv.DictReader(io.StringIO(text))` — читает CSV из строки, каждая строка — словарь
  «заголовок колонки → значение». `io.StringIO` делает из строки объект, похожий на файл.
- [Строка 15](../../job_finder/sources.py#L15): `csv.field_size_limit(10_000_000)`. По умолчанию модуль
  `csv` отказывается читать поле длиннее 131 072 символов, а HTML-описание может быть длинным.
- `remote == "True"` — в CSV всё строки, поэтому сравнение со строкой `"True"`.
- **Декодирование** ([строка 107](../../job_finder/sources.py#L107)): берём сырые байты
  `response.content` и декодируем сами как `utf-8-sig`. Если бы мы взяли `response.text`,
  `requests` угадывал бы кодировку по заголовкам ответа и при отсутствии `charset` мог бы испортить
  чешские буквы. `utf-8-sig` дополнительно убирает BOM — невидимый символ в начале файла, который
  иначе приклеился бы к имени первой колонки.

### Himalayas — [parse 60](../../job_finder/sources.py#L60), [fetch 110](../../job_finder/sources.py#L110)

- Международный сайт удалённой работы. Параметры поиска — `config.HIMALAYAS_PARAMS`:
  `python`, страна CZ, уровни Entry-level и Mid-level, сначала новые.
- **Постраничная загрузка**: по 20 вакансий на страницу, страницы 1…`HIMALAYAS_MAX_PAGES` (10).
  Перед каждой страницей, кроме первой, — пауза 1 с (`time.sleep(1)`): сайт ограничивает частоту
  запросов. Цикл останавливается на первой пустой странице.
- `{**config.HIMALAYAS_PARAMS, "page": page}` — новый словарь: все параметры из настроек плюс номер
  страницы. Сам словарь в `config` не меняется.
- `city`: если есть ограничения по странам, к «Remote» дописываются до трёх стран, а при большем
  числе — « …». Пример: `Remote (Czechia, Slovakia, Poland …)`.
- `pubDate` — число секунд с 1970 года (иногда строкой, поэтому `int(...)`).
  `datetime.fromtimestamp(..., timezone.utc).strftime("%Y-%m-%d")` превращает его в дату по UTC.
- `url` берётся из `guid` — это ссылка на страницу вакансии на самом himalayas.app (Himalayas
  просит вести пользователей к ним).

### Jobicy — [parse 76](../../job_finder/sources.py#L76), [fetch 122](../../job_finder/sources.py#L122)

- Удалённая работа, один запрос: 50 вакансий, гео `czechia`, отрасль `dev`.
- Разбор записан как *list comprehension* — выражение `[Job(...) for item in ...]` вместо цикла.

### Working Nomads — [parse 87](../../job_finder/sources.py#L87), [fetch 126](../../job_finder/sources.py#L126)

- Отдаёт **список** последних вакансий всех категорий без параметров поиска, поэтому фильтруем у себя:

### Общий запрос `_get(url, params)` — [строка 99](../../job_finder/sources.py#L99)

```python
response = requests.get(url, params=params, headers=HEADERS, timeout=config.HTTP_TIMEOUT)
response.raise_for_status()
```

- `params` — словарь превращается в строку запроса `?q=python&country=CZ…`.
- `HEADERS` ([строка 16](../../job_finder/sources.py#L16)) — свой `User-Agent` вместо стандартного
  `python-requests/…`, чтобы владельцы открытых API видели, что за программа к ним ходит.
- `timeout=30` — без таймаута зависший сайт заморозил бы обновление навсегда.
- `raise_for_status()` — если ответ 4xx или 5xx, выбрасывается исключение `HTTPError`.

> **Справка: `.get()` против `[]` в разборщиках.** Обязательные поля читаются через `item["url"]`:
> если поля нет, `KeyError` — и весь источник считается упавшим (лучше заметить смену формата API,
> чем молча записать мусор). Необязательные — через `item.get("…")`: если поля нет, будет `None`,
> а `None` потом превратится в `""` в `__post_init__`.

## Список источников и приоритет — [строка 131](../../job_finder/sources.py#L131)

SOURCES = [

## Ключ «та же вакансия» `same_job_key(company, title)` — [строка 143](../../job_finder/sources.py#L143)

Возвращает пару (компания, название) после нормализации: нижний регистр, лишние пробелы схлопнуты.
Этим ключом пользуются два места: `dedupe` ниже и окно — для пометки «↻ / You already applied»
у найденной вакансии с той же компанией и названием, что у отклика. Одно правило на оба случая.

## Удаление дублей `dedupe(fetched)` — [строка 148](../../job_finder/sources.py#L148)

Одна вакансия часто публикуется на нескольких агрегаторах с разными ссылками. Ссылка как ключ
не подходит, поэтому ключ — пара **(компания, название)** после нормализации:

```python
def _norm(text):                      # строка 139
    return " ".join(text.lower().split())
```

`lower()` — нижний регистр; `split()` без аргументов режет по любым пробелам и переводам строк,
`" ".join` склеивает обратно через один пробел. Так `" ACME "` и `"acme"`, `"Python  Dev"` и
`"python dev"` дают одинаковый ключ.

Алгоритм: идём по источникам в порядке словаря (Python сохраняет порядок вставки), внутри — по
вакансиям; множество `seen` хранит уже встреченные ключи. Первая встреча — оставляем, повторная —
выбрасываем. Заодно убираются повторы **внутри** одного источника.

Пример (из теста):

```
вход:   junior.guru: [ACME / Python Dev (u1)]
        Himalayas:   [" acme " / "python  dev" (u2),  ACME / Other (u3)]
выход:  junior.guru: [u1]
        Himalayas:   [u3]          ← u2 — тот же ключ, что у u1
```

## `fetch_all()` — [строка 162](../../job_finder/sources.py#L162)

```python
for name, fetch in SOURCES:
    try:
        fetched[name] = fetch()
    except Exception as error:
        log.exception("Источник %s не загрузился", name)
        errors[name] = str(error)[:150]
return dedupe(fetched), errors
```

- Каждый источник — в своём `try`: упал один (сайт недоступен, сменился формат) — остальные
  работают.
- `log.exception` пишет в лог сообщение **и полную трассировку**.
- В `errors` — коротко (до 150 символов), это пойдёт в строку состояния окна.
- Упавший источник **не попадает** в `fetched`. Это важно для базы: `worker` вызывает
  `db.save_jobs` только для загруженных источников, поэтому вакансии упавшего источника в базе
  остаются как были (не становятся неактивными).

Возвращается кортеж: (словарь «источник → вакансии без дублей», словарь «источник → текст ошибки»).

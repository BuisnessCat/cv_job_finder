# Job Finder — дизайн

Дата: 2026-10-12. Статус: согласован в обсуждении, ждёт проверки пользователем.

## 1. Цель и рамки

Личная утилита для Windows, которая вместо пользователя следит за вакансиями и как можно раньше
показывает только подходящие. Инструмент для одного человека, не для портфолио: главное —
надёжность и экономия времени.

**Пользователь:** студент 2-го курса прикладной информатики в Праге, не гражданин ЕС, имеет
свободный доступ к чешскому рынку труда (студент очной формы). Ищет стажировку, junior или
part-time позицию Python-разработчика: Прага (офис/гибрид) или удалённо внутри Чехии/ЕС.
Языки: английский B2, чешский B1, русский родной. Опыта коммерческой разработки нет.

**Источник правды — `master_cv.md`** в корне проекта: целевые роли, навыки, проекты, языки,
правила адаптации резюме. При изменении файла профиль и оценки пересчитываются.

**Жёсткие ограничения**
- Работает локально на компьютере пользователя (Windows 11, Ryzen 5 5600, RTX 3060 12 ГБ,
  16 ГБ ОЗУ, Python 3.11). Интерфейс на русском.
- Без Telegram, без внешних серверов, без Docker. Данные — один файл SQLite.
- Сбор в фоне, автозапуск при входе в Windows, уведомления Windows.
- Ничего не отправляет от имени пользователя. LinkedIn — только сохранённая ссылка.
- Автоматический сбор — только там, где это разрешают правила сайта: официальные API, RSS,
  публичные фиды и email-оповещения. Где нельзя — сохранённая ссылка, которую пользователь
  открывает сам.
- Личные данные (`master_cv.md`, база, готовые документы, `.env`) — в `.gitignore`.

**Критерии успеха**
1. Пользователь не проверяет сайты вручную: открывает приложение по уведомлению или когда удобно.
2. Новая вакансия из источника оценена не позже чем через 2 часа плюс время оценки после того,
   как источник её отдал. Для API компаний это примерно время публикации, для junior.guru и
   оповещений StartupJobs — их собственная задержка (до суток).
3. Уведомление приходит только о вакансиях с оценкой ≥ порога (по умолчанию 4), прошедших фильтры.
4. Ни одна вакансия не отсеивается незаметно: у каждой отсеянной видны причина и цитата,
   её можно вернуть.
5. После перезагрузки компьютера всё работает без действий пользователя.
6. Установка — один `install.bat`.

### 3.2. Источники этапа 1

**junior.guru (`sources/juniorguru.py`).** Раз в цикл сбора загружает CSV и разбирает строки в
`RawJob`. Внешние ID из `external_ids_*` сохраняются для дедупликации. HTML-описание
переводится в текст.

**Оповещения StartupJobs (`sources/startupjobs_email.py`).**
- Подключение по IMAP (`imaplib`), ящик открывается **только на чтение** (`EXAMINE`,
  `BODY.PEEK`). Письма не помечаются прочитанными и не удаляются.
- Читает одну папку из `.env` (`IMAP_FOLDER`), например метку Gmail с фильтром на отправителя
  StartupJobs.
- Обрабатывает только письма от домена `startupjobs.cz`. Обработанные письма запоминаются по
  паре (UIDVALIDITY, UID).
- Из письма извлекаются название, компания и ссылка. Ссылки ведут через трекинг-редиректы,
  поэтому их нужно развернуть до канонического `https://www.startupjobs.cz/nabidka/<id>/...`.
  Переходы — только на домены из allowlist (`startupjobs.cz` и домен его трекинга, который
  определится по реальному образцу письма).
- Новая вакансия загружается один раз через `detail.py` (раздел 3.3).
- Формат письма неизвестен до появления реального образца, поэтому разборщик пишется по
  обезличенному образцу из `tests/fixtures/`. Если письмо не удаётся разобрать, оно пропускается
  с записью в лог, остальные обрабатываются.

**Карьерные API компаний (`sources/ats.py`).** Список компаний хранится в
`config/companies.toml`, у каждой указаны платформа и slug. Эндпоинты:
- Greenhouse: `GET https://boards-api.greenhouse.io/v1/boards/{slug}/jobs?content=true`
- Lever: `GET https://api.lever.co/v0/postings/{slug}?mode=json`
- Ashby: `GET https://api.ashbyhq.com/posting-api/job-board/{slug}`
- Workable: `GET https://apply.workable.com/api/v1/widget/accounts/{slug}`

Компании отдают вакансии по всему миру, поэтому ещё до ИИ работает предфильтр по локации
(раздел 6). Начальный список из 15–30 пражских IT-компаний составляется при планировании и
согласуется с пользователем. Компания с неверным slug отмечается в статусе источника и не мешает
остальным.

### 3.3. Загрузка страницы вакансии (`detail.py`)

- Используется, только если у вакансии нет полного текста (сейчас это StartupJobs).
- Один запрос на вакансию, не чаще одного раза в 5 секунд на домен, честный User-Agent
  `jobfinder-personal/1.0`, таймаут 20 с.
- Сначала ищется JSON-LD `JobPosting`, иначе берётся основной текст страницы (BeautifulSoup).
- Если загрузить не удалось, вакансия оценивается по фрагменту из письма с пометкой
  «оценка по краткому описанию», загрузка повторяется при следующем сборе (до 3 попыток).

## 4. Архитектура

Один процесс `pythonw`, автозапуск ярлыком в папке «Автозагрузка» (без прав администратора).

```
master_cv.md ──► profile ──(навыки, ключевые слова, хэш)───────────────┐
                                                                     ▼
поток-планировщик (проверка раз в минуту: «пора?») ──► collector ──► sources/* ──► нормализация
                                                                     │
                                         dedup ──► SQLite (только новые идут дальше)
                                                                     │
                                         detail (если нет полного текста)
                                                                     │
                                         prefilter (без ИИ) ──► «Отсеянные»
                                                                     │
                                         evaluate (LM Studio, JSON-схема)
                                                                     │
                                         filters (жёсткие условия, пороги) ──► «Отсеянные»
                                                                     │
                                         notify (score ≥ порога) + список в окне
```

**Потоки внутри процесса**
- Главный поток: окно pywebview (обязательно в главном потоке).
- Поток uvicorn: FastAPI на `127.0.0.1:8765`.
- Поток трея: pystray (`run_detached`).
- Поток планировщика: раз в минуту проверяет, прошло ли с последнего начала сбора не меньше
  интервала (по умолчанию 2 часа). Это покрывает старт, выход из сна и пропущенные сборы.
  Одновременно идёт только один сбор (lock).

**Один экземпляр.** При старте процесс пытается занять порт 8765. Если порт занят работающим
экземпляром, новый процесс отправляет ему `POST /api/show` (показать окно) и завершается.

## 6. Профиль, предфильтр, оценка, жёсткие фильтры

### 6.1. Профиль (`profile.py`)

Из `master_cv.md` по заголовкам `## ` извлекаются:
- **Target**: роли и локации;
- **Skills**: строки `- Навык — уровень и доказательства`; строка «In progress, NOT to be
  presented as done» — отдельный список `in_progress`;
- **Languages**;
- **Work authorization**;
- **Rules for tailored versions**: целиком, для этапа 2.

Раздел Contact в промпты не передаётся. Хэш считается по содержимому файла.

Ключевые слова для предфильтра — названия навыков плюс словарь ролей: `python, backend,
back-end, junior, intern, internship, trainee, stáž, stážista, student, brigáda, absolvent,
part-time`. Профиль проверяется в начале каждого сбора и при открытии окна. Если разбор не
удался (нет раздела Skills или Target), используется прошлая успешная версия профиля, в окне
появляется предупреждение.

**При изменении хэша** все вакансии в статусах `new`, `later`, `pending_eval`, `eval_error` и
отсеянные предфильтром за последние 30 дней снова проходят предфильтр и оценку, самые свежие
первыми. Повторное уведомление приходит, только если вакансия впервые достигла порога.

### 6.2. Предфильтр (`prefilter.py`, без ИИ)

Вакансия отсеивается с сохранённой причиной, если:
1. **Название** содержит маркер старшинства: `senior, lead, principal, staff, head of, director,
   architect, manager` (без учёта регистра, по границам слов). Причина: «senior/lead в названии».
2. **Локация** явно вне зоны: в `location`/`remote` нет Праги/Чехии/удалёнки, а указан
   конкретный другой город или страна. Пустая или неясная локация **не** отсеивается.
3. **Нет пересечения по навыкам**: ни название, ни описание не содержат ни одного навыка из
   профиля и ни одного слова из словаря ролей.

Прага распознаётся по городу или региону (в CSV junior.guru есть `locations_*_region`), без
учёта диакритики, включая `Prague`, `Praha 1–22` и районы Праги (`Vršovice`, `Karlín`,
`Smíchov`, `Holešovice` и т. д., список в `prefilter.py`). Это же правило используется в
жёстком фильтре локации (6.4).

### 6.3. Оценка (`evaluate.py`)

Один запрос на вакансию. Системный промпт: профиль без Contact, шкала, правила. Пользовательское
сообщение: название, компания, локация и текст вакансии. Ответ — строго по JSON-схеме
(`response_format: json_schema`), проверяется моделью Pydantic `Evaluation`:

| Поле | Тип и значения |
|---|---|
| `czech_required` | `none` / `A1-A2` / `B1` / `B2` / `C1+` / `native` / `unknown` |
| `czech_quote` | Строка или `null`: цитата из вакансии |
| `min_years` | Число или `null` |
| `years_quote` | Строка или `null` |
| `seniority` | `intern` / `junior` / `medior` / `senior` / `unknown` |
| `eu_citizenship_required` | `true` / `false` / `null` |
| `right_to_work_country` | Код страны, если требуется право на работу в конкретной стране, иначе `null` |
| `work_auth_quote` | Строка или `null` |
| `work_mode` | `onsite` / `hybrid` / `remote` / `unknown` |
| `cities` | Список строк |
| `remote_region` | `CZ` / `EU` / `worldwide` / код страны / `null` |
| `posting_language` | `cs` / `en` / `other` |
| `score` | Целое 1–5 |
| `why` | 1–3 короткие фразы по-русски |
| `missing` | Список: чего не хватает, по-русски |
| `matched_keywords` | Ключевые слова вакансии, которые реально есть в профиле |

**Шкала** (в промпте):
- 5 — junior/стажёр, Python backend, стек сильно совпадает, условия подходят;
- 4 — хорошее совпадение с 1–2 пробелами;
- 3 — частичное: Python, но QA/data/другая специализация, или желателен опыт больше имеющегося;
- 2 — слабое совпадение;
- 1 — не подходит.

Пункты `in_progress` считаются пробелами, а не навыками.

**Защита от выдумок (код)**
- `matched_keywords` фильтруется: остаются только слова, которые совпадают (без учёта регистра,
  с простыми синонимами вроде `Postgres` ↔ `PostgreSQL`) с навыками профиля.
- Каждая цитата (`*_quote`) ищется в тексте вакансии после нормализации пробелов и регистра.
  Если её нет, соответствующее поле становится `unknown`/`null`, вакансия получает пометку
  «извлечение не подтверждено».

**Сбои.** Невалидный JSON или ответ, не прошедший Pydantic, — один немедленный повтор. Если
снова неудача — статус `eval_error`, повтор при следующих сборах, всего не больше 3 попыток,
дальше вакансия остаётся в `eval_error` и видна в окне. Текст длиннее лимита (по умолчанию
12 000 символов) обрезается с пометкой «текст обрезан».

### 6.4. Жёсткие фильтры (`filters.py`)

Решение принимает код по извлечённым полям. Пороги хранятся в настройках.

| Условие | Отсеять | Пометка «под вопросом» | Проходит |
|---|---|---|---|
| Чешский | `C1+`, `native` | `B2` | `none`, `A1-A2`, `B1`, `unknown` |
| Опыт | `min_years ≥ 3` или `seniority = senior` | `min_years = 2` | меньше 2, `null` |
| Локация | `onsite`/`hybrid` и в `cities` нет Праги (при непустом списке); `remote` с `remote_region` = код страны ≠ `CZ` | `work_mode = unknown` и нет городов | Прага; `remote` с `CZ`/`EU`/`worldwide` |
| Право на работу | `eu_citizenship_required = true` или `right_to_work_country` ≠ `CZ` | — | иначе |

Отсеянная вакансия хранит причину и цитату и видна во вкладке «Отсеянные». Кнопка «Вернуть»
переводит её в `new` и ставит `manual_override` (фильтры к ней больше не применяются).

## 7. Данные (SQLite, `data/jobfinder.db`, режим WAL)

| Таблица | Основные поля |
|---|---|

| `email_seen` | `folder`, `uidvalidity`, `uid`, `processed_at` |
| `settings` | `key`, `value` |
| `profile_state` | `hash`, `parsed` (JSON), `updated_at` |

**Статусы вакансии:** `pending_eval` → (`filtered` | `new`) → `later` | `applied` | `skipped`;
плюс `eval_error`. Предфильтр переводит вакансию сразу в `filtered`.

**Дедупликация** (`dedup.py`)
- Канонический URL: нижний регистр хоста, без `utm_*` и фрагмента, без завершающего `/`.
- Внешние ID: из junior.guru (`jobscz#ID` → `jobscz:ID`), из URL jobs.cz `/rpd/ID/`, из URL
  StartupJobs `/nabidka/ID/`, ID из ATS.
- Запасной ключ: нормализованные компания и название (нижний регистр, без диакритики,
  без пунктуации и суффиксов `s.r.o.`, `a.s.`).
- Совпадение хотя бы одного ключа означает ту же вакансию: добавляется источник, новые ключи
  привязываются, повторная оценка не делается.
- Вакансии в статусах `skipped`/`applied` при повторном появлении в «Новые» не возвращаются.

**Обслуживание**
- Раз в сутки копия базы в `data/backups/` (через `sqlite3` backup API), хранятся последние 7.
- Логи — `data/logs/app.log`, ротация 5 × 1 МБ.

## 8. LM Studio (`llm.py`)

- Адрес `http://localhost:1234`, имя модели в настройках. По умолчанию уже установленная
  `qwen/qwen3.8-27b`, окончательный выбор — по итогам `bench` (раздел 10).
- Перед оценкой: `GET /v1/models`. Если сервер не отвечает — `lms server start` (путь
  `%USERPROFILE%\.lmstudio\bin\lms.exe`), ожидание до 60 с.
- Модель загружается по требованию с автовыгрузкой после 10 минут простоя (TTL), чтобы
  видеопамять не была занята постоянно.
- Режим «размышлений» модели при оценке отключён. Конкретный способ для выбранной модели
  определяется в задаче `bench`.
- Если LM Studio недоступна, сбор всё равно идёт, вакансии ждут в `pending_eval`, в окне
  статус «LM Studio недоступна». Если недоступна 3 сбора подряд — одно уведомление.
- Вакансии оцениваются по одной, уведомление отправляется сразу после оценки каждой.

## 9. Интерфейс

**Окно приложения:** pywebview (Edge WebView2), заголовок «Job Finder». Внутри — страницы
локального сервера. Закрытие окна прячет его в трей, выход — через меню трея. Запасной вход —
`http://127.0.0.1:8765` в браузере.

**Вкладки**
- **Новые** (по умолчанию): карточки, сортировка по оценке, при равенстве — по свежести.
  - На карточке: оценка, название, компания, город/формат, источники, давность, пометки ⚠.
  - Раскрывающиеся блоки «Почему», «Чего не хватает», «Совпавшие ключевые слова», «Условия»
    (извлечённые поля с цитатами).
  - Кнопки «Подаюсь», «Позже», «Пропуск», ссылка «Открыть оригинал» (в системном браузере).
  - Фильтр «показывать от оценки N», по умолчанию 3. Видны вакансии, у которых
    `first_seen_at` не старше 30 дней. Давность на карточке считается от `posted_at`, если
    источник его отдаёт, иначе от `first_seen_at`.
- **Позже**: те же карточки.
- **Подаюсь**: список со ссылками на отклик (документы — этап 2, статусы — этап 3).
- **Отсеянные**: причина, этап (предфильтр/фильтр), цитата, кнопка «Вернуть».
- **Источники**: по каждому источнику — время последнего сбора, статус, текст ошибки, число
  новых; статус LM Studio и профиля (`master_cv.md` разобран / ошибка); кнопка «Собрать
  сейчас»; очередь оценки. Блок сохранённых ссылок появится на этапе 2.
- **Настройки**: порог уведомлений (4), чешский (отсев от C1+), опыт (отсев от 3 лет),
  интервал сбора (2 ч), модель LM Studio, IMAP-сервер, логин и папка. Пароль IMAP хранится
  только в `.env`.

**Трей:** иконка с подсказкой «Последний сбор: ЧЧ:ММ · подходящих новых: N». Меню: Открыть,
Собрать сейчас, Приостановить/Возобновить сбор, Выход.

**Уведомления** (`windows-toasts`):
- заголовок «★{score} {title} — {company}», текст — первая фраза `why` и пометка
  «⚠ под вопросом: …», если она есть;
- клик показывает окно и открывает карточку вакансии;
- если за один сбор подходящих больше 3, приходит одно сводное уведомление «N новых
  подходящих вакансий».

**Безопасность:** сервер слушает только `127.0.0.1`. POST-запрос отклоняется (403), если в нём
есть заголовок `Origin` и он не равен `http://127.0.0.1:8765` или `http://localhost:8765`.
Браузеры всегда отправляют `Origin` в POST, поэтому чужой сайт не сможет «нажать кнопку».
Запрос без `Origin` (например, `POST /api/show` от второго экземпляра) принимается. Тексты вакансий и писем —
недоверенные данные: в шаблонах экранируются, LLM не получает никаких инструментов.

## 10. Надёжность и тестирование

**Надёжность**
- Каждый источник в цикле сбора выполняется в отдельном `try`. Ошибка пишется в `runs` и лог и
  не останавливает остальные источники.
- Сетевые запросы: таймаут 20 с, 2 повтора с паузой 2 и 5 с.
- Источник падает 3 сбора подряд → одно уведомление «Источник X не работает: …».
  Следующее — только после восстановления и нового сбоя.
- Каждое письмо, каждая вакансия и каждая оценка фиксируются в базе сразу (отдельной
  транзакцией), поэтому выключение компьютера посреди сбора ничего не ломает.
- Необработанное исключение в любом потоке пишется в лог, процесс продолжает работать.
  Если исключение в главном потоке, процесс завершается; следующий старт — при входе в Windows.

**Автотесты (pytest, без сети и LM Studio)**
- `profile`: синтетический `tests/fixtures/cv.md` (реальное резюме в git не попадает).
- `dedup`: канонизация URL; `jobscz#ID` ↔ `jobs.cz/rpd/ID`; ключ «компания+название».
- `prefilter`: маркеры старшинства, локация, отсутствие пересечения.
- `filters`: таблица граничных случаев из раздела 6.4.
- `evaluate`: поддельный LLM-клиент — валидный ответ; невалидный с повтором; `eval_error` после
  3 попыток; выброс выдуманных ключевых слов; цитата не найдена → `unknown`.
- Разборщики на сохранённых образцах: CSV junior.guru, ответы четырёх ATS API, HTML страницы
  StartupJobs, обезличенные письма StartupJobs.
- `web`: FastAPI TestClient — смена статусов, «Вернуть», отказ на POST с чужим `Origin`.

**Ручная проверка модели (`python -m jobfinder.bench`)** — **первая задача реализации**.
Берёт 10 реальных вакансий (junior.guru и ATS), показывает секунды на вакансию и результаты
оценки. Если оценка одной вакансии дольше ~2 минут или результаты явно плохие, пользователю
предлагается модель поменьше, которая целиком помещается в 12 ГБ видеопамяти. Там же
выясняется, как отключить «размышления» у выбранной модели.

**Ручная приёмка этапа 1**
- `install.bat` в чистом окружении;
- автозапуск после выхода из Windows и повторного входа;
- клик по уведомлению открывает карточку;
- сон и пробуждение — пропущенный сбор запускается;
- закрытие окна → трей → «Открыть» → «Выход»;
- изменение `master_cv.md` → переоценка.

`install.bat`:
1. создаёт `.venv` через `py -3.11`, ставит `requirements.txt`;
2. копирует `.env.example` в `.env`, если `.env` ещё нет;
3. создаёт ярлык `Job Finder.lnk` (цель `.venv\Scripts\pythonw.exe -m jobfinder`, рабочая папка —
   проект) в `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` через PowerShell
   `WScript.Shell`;
4. запускает приложение.

**Подготовка со стороны пользователя** (до задачи про оповещения StartupJobs):
- аккаунт на StartupJobs и оповещения (параметры подскажет приложение по профилю: Back-End,
  Python, Praha + Remote, Junior);
- метка или папка в почте с фильтром на письма StartupJobs;
- для Gmail — включённая двухфакторная аутентификация и пароль приложения, вписанный в `.env`;
- одно реальное письмо-оповещение для образца разборщика.

## 13. Риски

| Риск | Что делаем |
|---|---|
| Локальная модель медленная или неточная | `bench` первой задачей; запасной план — модель поменьше; пороги и шкала настраиваются |
| Неизвестен формат писем StartupJobs | Разборщик по реальному образцу; неразобранные письма видны в логе и статусе источника |
| Меняется формат CSV junior.guru, ATS API или страницы StartupJobs | Ошибка видна в статусе источника; уведомление после 3 сбоев подряд; тесты на образцах |
| Мало вакансий в источниках этапа 1 | Список ATS-компаний расширяется в конфиге; этап 2 добавляет источники и ссылки |
| Предфильтр отсекает лишнее | Все отсеянные видны с причиной, можно вернуть; правила консервативные (неясное не отсеивается) |

# Подбор вакансий — дизайн

Дата: 2026-10-13. Заменяет спек и план от 2026-10-12: они оказались слишком сложными и отменены.

## 1. Что делаем

Десктопное приложение для Windows: обычное окно на PySide6, интерфейс на английском (надписи — в разделе 12). Открывается
двойным кликом по ярлыку на рабочем столе, без окна консоли; закрыл окно — процесс завершился.

При открытии и по кнопке «Обновить» приложение:

1. скачивает вакансии из четырёх агрегаторов с открытым API;
2. без ИИ отбрасывает вакансии, где нет ни одного навыка из `master_cv.md`;
3. оценивает остальные локальной моделью в LM Studio по `master_cv.md`;
4. показывает вакансии с оценкой не ниже порога (по умолчанию 5) по убыванию оценки;
5. после отклика вакансию можно кнопкой «Подался» перенести во вкладку «Мои отклики» и потом
   отметить итог: приняли или отказали. Так при следующих поисках видно, куда уже подавались.
   К отклику можно записать заметку; видно, сколько дней ждём ответа, а через 14 дней приложение
   подсказывает напомнить о себе или закрыть отклик;
6. помечает вакансии, которые появились с прошлого закрытия приложения;
7. на вкладке Insights показывает, чего чаще всего не хватает и что чаще всего требуют (раздел 13).

Уже оценённые вакансии повторно не оцениваются, пока не изменятся `master_cv.md`, правила оценки
или модель.

**Не делаем:** сбор по расписанию, автозапуск, трей, уведомления, чтение почты, напоминания об откликах вне окна (уведомления, письма),
генерацию резюме и писем, замеры моделей, сложные проверки ответов модели, карьерные страницы
компаний, LinkedIn, кнопку «вернуть скрытую вакансию».

## 2. Источники

Все — публичные API без ключа. Порядок в таблице — приоритет при удалении дублей.

| # | Источник | Запрос | Отбор на нашей стороне | Примерный объём |
|---|---|---|---|---|
| 1 | junior.guru | `GET https://junior.guru/api/jobs.csv` | только Прага (регион «Praha» среди мест вакансии) или удалёнка | ~50, из них ~20 в Праге; junior, в основном на чешском |
| 2 | Himalayas | `GET https://himalayas.app/jobs/api/search?q=<главный навык>&country=CZ&seniority=<по уровням>&sort=recent&page=N` (раздел 15.5) — по 20 на страницу, страницы 1…10, пауза 1 с, остановка на пустой странице | — | до 200 (сейчас подходят ~210), удалёнка, доступная из Чехии, английский |
| 3 | Jobicy | `GET https://jobicy.com/api/v2/remote-jobs?count=50&geo=czechia&industry=dev` | — | ~16, удалёнка, доступная из Чехии, английский |
| 4 | Working Nomads | `GET https://www.workingnomads.com/api/exposed_jobs/` | `category_name == "Development"` | ~20 из последних 50, английский |

Параметры запросов Himalayas и Jobicy лежат в `config.py`. Чтобы сократить время первой оценки,
можно оставить у Himalayas только `Entry-level` (тогда их ~18).

**Приведение к общей записи `Job`:** `url`, `source`, `title`, `company`, `city`, `published`
(дата `YYYY-MM-DD`), `description` (обычный текст). HTML описаний переводится в текст через
BeautifulSoup (`get_text("\n")`).

| Поле | junior.guru (CSV) | Himalayas | Jobicy | Working Nomads |
|---|---|---|---|---|
| url | `url` | `guid` (страница на himalayas.app) | `url` | `url` |
| title | `title` | `title` | `jobTitle` | `title` |
| company | `company_name` | `companyName` | `companyName` | `company_name` |
| city | «Praha», если среди `locations_N_region` есть «Praha»; иначе «Удалённо» при `remote` = True; иначе вакансия пропускается | «Удалённо» + страны из `locationRestrictions`, если они есть | «Удалённо: » + `jobGeo` | «Удалённо: » + `location` |
| published | дата из `first_seen_at` | `pubDate` (unix-секунды) → дата | первые 10 символов `pubDate` | первые 10 символов `pub_date` |
| description | `description_html` | `description` | `jobDescription` | `description` |

**Дубли.** После загрузки всех источников повторы убираются по ключу «компания + название»
(нижний регистр, пробелы схлопнуты). Остаётся запись из источника с меньшим номером.

**Ссылка на источник.** Himalayas и Jobicy просят указывать их как источник и вести на их страницу
вакансии. В деталях вакансии всегда видно «Источник: …», а кнопка «Открыть вакансию» открывает
`url` из источника.

## 3. Ход одного обновления

Выполняется в фоновом потоке; окно остаётся отзывчивым, кнопка «Обновить» на это время неактивна.

1. **Загрузка.** Каждый источник загружается в своём `try`. Ошибка источника попадает в строку
   состояния, остальные источники продолжают работу.
2. **Запись в базу.** Вакансии из всех успешно загруженных источников проходят удаление дублей
   и записываются в базу (`upsert` по `url`; оценка и пометка «скрыта» при этом сохраняются).
   У каждого успешно загруженного источника вакансии, которых нет в новой выборке, получают
   `active = 0` и больше не показываются. Вакансии источника, загрузка которого не удалась,
   остаются как были.
3. **Очередь на оценку.** Читается `master_cv.md` и считается ключ оценки `cv_hash` — SHA-256
   текста резюме вместе с моделью и правилами оценки (`llm.fingerprint()`). В очередь
   идут вакансии с `active = 1`, `hidden = 0`, без отклика (`status IS NULL`), у которых нет оценки или `cv_hash` оценки не
   совпадает с текущим, и в которых нашёлся хотя бы один навык (раздел 4). Сначала самые новые.
4. **Оценка.** Если очередь не пуста: `llm.prepare()`, затем по одной вакансии `llm.evaluate()`.
   Каждая оценка сразу сохраняется и отправляется в окно; в строке состояния — «Оценено N из M».
   В конце — `llm.release()` (модель выгружается из видеопамяти), даже если были ошибки.

## 4. Отсев по навыкам (`skills.py`)

**Список навыков** берётся из раздела `## Skills` файла `master_cv.md` (до следующего заголовка
`## `):

- каждая строка вида `- <навыки> — <пояснение>`: берётся часть до « — », делится по запятым,
  от каждого элемента берётся первое слово;
- строки, начинающиеся с `Concepts` и `In progress`, пропускаются.

Для текущего резюме получается: Python, SQL, FastAPI, Pydantic, SQLAlchemy, Alembic, PostgreSQL,
Docker, Git, GitHub, requests, BeautifulSoup.

**Совпадение:** навык ищется в названии и описании вакансии как целое слово без учёта регистра:
регулярное выражение `(?<!\w)навык(?!\w)`. Например, `Git` не совпадает с `GitLab`, а `SQL`
совпадает с `T-SQL`, но не с `MySQL`. Вакансия проходит, если совпал хотя бы один навык.

## 5. Оценка моделью (`llm.py`)

**Единственное место вызова модели.** Модуль даёт три функции:

```python
prepare() -> None                      # подготовить модель к работе
evaluate(cv_text: str, job: Job) -> dict  # оценить одну вакансию
release(wait: bool = True) -> None     # освободить ресурсы; wait=False — не ждать (при закрытии окна)
```

Чтобы перейти на другую модель, достаточно поменять `MODEL` в `config.py`. Чтобы перейти на
Claude API, достаточно переписать эти три функции: `prepare` и `release` станут пустыми,
`evaluate` будет вызывать API.

**Модель:** `mistralai/ministral-3-8b` (instruct-версия без «размышлений», ~6,5 ГБ, целиком
помещается в 12 ГБ RTX 3060). Скачивается один раз командой `lms get` во время реализации;
пользователь дал согласие на это скачивание.

**Управление LM Studio** (вызовы `lms.exe` из `%USERPROFILE%\.lmstudio\bin` через `subprocess`
с флагом `CREATE_NO_WINDOW`, чтобы не мелькали консоли):

- `prepare()`: если `GET http://localhost:1234/v1/models` не отвечает, выполняется
  `lms server start --port 1234` и сервер ждётся до 30 с. Если модели с идентификатором
  `job-finder` нет в `lms ps --json`, выполняется
  `lms load mistralai/ministral-3-8b --identifier job-finder --context-length 8192 --gpu max --ttl 300 -y`.
  `--ttl 300` — страховка: если приложение закроется посреди загрузки модели, LM Studio сама
  выгрузит её после 5 минут простоя.
- `release()`: `lms unload job-finder`. Сервер LM Studio остаётся работать: без загруженной
  модели он не занимает видеопамять.

**Запрос:** `POST http://localhost:1234/v1/chat/completions` с `temperature: 0`,
`max_tokens: 700` и `response_format` типа `json_schema` (LM Studio тогда возвращает JSON
строго по схеме). Таймаут — 120 с.

- Системное сообщение: роль и правила оценки, затем полный текст `master_cv.md`. Оно одинаковое
  для всех вакансий, поэтому LM Studio переиспользует уже обработанное начало запроса.
- Сообщение пользователя: название, компания, город, источник и описание вакансии, обрезанное
  до 8000 символов.
- Правила оценки в промпте: определить суть роли и 2–4 действительно обязательных требования;
  длинные списки технологий считать пожеланиями и не снижать оценку за второстепенные инструменты;
  засчитывать близкие навыки (Django/Flask ≈ FastAPI, MySQL/MSSQL ≈ PostgreSQL); на junior-позициях
  недостающие технологии — повод учиться, а не отказ. Сильно снижать оценку только за настоящие
  блокеры: 2+ года опыта или mid/senior, другой основной язык или область, обязательный свободный
  чешский или английский C1+, офис вне Праги без удалёнки, гражданство или резидентство другой
  страны. Явно перечислено, что блокером не является: офис или гибрид в Праге, удалёнка из Чехии
  или ЕС, разрешение на работу, английский B2, чешский B1. Шкала: 9–10 — junior или стажировка,
  основа стека совпадает, блокеров нет; 7–8 — основа совпадает, не хватает технологий, которым
  можно научиться; 5–6 — смежная роль или другой фреймворк, но реально попробовать; 3–4 —
  серьёзный пробел; 1–2 — не подходит. Не больше 5 коротких пунктов в списке, обычный текст без
  Markdown, все тексты на английском (раздел 12).

**Схема ответа:**

| Поле | Тип | Смысл |
|---|---|---|
| `score` | целое 1–10 | насколько кандидат подходит |
| `summary` | строка | коротко: почему такая оценка (1–2 предложения) |
| `have` | список строк | требования вакансии, которые у кандидата есть |
| `missing` | список строк | требования, которых не хватает |
| `risks` | список строк | что может отсечь: свободный чешский, много лет опыта, нужно гражданство или резидентство ЕС либо другой страны, офис вне Праги и т. п. |

Проверка ответа — только `json.loads` и `int(score)`. Если ответ не разобрался или запрос
упал, вакансия пропускается и попадёт в очередь при следующем обновлении.

## 6. Хранение (`db.py`)

Один файл SQLite `jobs.db` в корне проекта, одна таблица:

```sql
CREATE TABLE IF NOT EXISTS jobs (
    url         TEXT PRIMARY KEY,
    source      TEXT NOT NULL,
    title       TEXT NOT NULL,
    company     TEXT NOT NULL,
    city        TEXT NOT NULL,
    published   TEXT NOT NULL,      -- YYYY-MM-DD
    description TEXT NOT NULL,
    active      INTEGER NOT NULL DEFAULT 1,
    hidden      INTEGER NOT NULL DEFAULT 0,
    score       INTEGER,            -- NULL, пока не оценена
    evaluation  TEXT,               -- JSON-ответ модели
    cv_hash     TEXT,               -- ключ оценки: SHA-256 резюме, модели и правил
    status      TEXT,               -- отклик: NULL, 'applied', 'accepted', 'rejected'
    applied_at  TEXT,               -- дата отклика YYYY-MM-DD
    notes       TEXT,               -- заметка к отклику
    seen        INTEGER NOT NULL DEFAULT 0  -- 0 — появилась после прошлого закрытия окна (новая)
);
```

Если `jobs.db` создана до этих колонок, `init()` добавляет недостающие (`ALTER TABLE … ADD COLUMN`);
вакансии и оценки при этом сохраняются. При добавлении `seen` все уже имеющиеся вакансии сразу
отмечаются просмотренными (`seen = 1`), чтобы после обновления приложения список не стал целиком
«новым»; новые строки получают `seen = 0` по умолчанию.

**Новые вакансии** — строки с `seen = 0`. При закрытии окна просмотренными отмечаются все **оценённые**
вакансии (`UPDATE jobs SET seen = 1 WHERE seen = 0 AND score IS NOT NULL`), поэтому при следующем
запуске новыми будут только те, что пришли после этого. Ещё не оценённые (ждали в очереди, LM Studio
не поднялась) окно показать не могло — они остаются новыми до сессии, в которой их оценят. Правка
резюме и переоценка `seen` не меняют.

Каждая функция `db.py` открывает своё короткое соединение, поэтому базой можно пользоваться и из
окна, и из фонового потока.

**В списке найденных показываются** вакансии с `active = 1` (а с 2026-10-18 и пропавшие из источника не больше
недели назад, см. 14.6), `hidden = 0`, без отклика, `cv_hash` = текущий хеш и
`score >= MIN_SCORE`, по убыванию `score`, затем по убыванию `published`. Если ключ оценки изменился,
старые оценки скрываются и появляются снова по мере переоценки.

**Во вкладке «Мои отклики»** — все вакансии со статусом отклика, независимо от `active`, `hidden` и
`cv_hash`: отклик не пропадает, даже если вакансия исчезла с сайта или поменялось резюме. Сортировка —
по убыванию `applied_at`. Показываются сохранённые оценка и разбор.

## 7. Окно

Заголовок «Job Finder», размер около 1200×750.

- **Верхняя полоса:** кнопка «Обновить», переключатель «Найденные · N | Мои отклики · M» (числа —
  сколько строк в каждом списке), строка состояния, полоса прогресса (видна только во
  время оценки). Примеры строки состояния: «Загружаю вакансии…», «Запускаю LM Studio…»,
  «Оценено 12 из 270», «Готово: 18 подходящих из 259 оценённых». Ошибки источников и LM Studio дописываются в эту
  строку и остаются в ней до следующего обновления.
- **Слева** — таблица с колонками Оценка, Вакансия, Компания, Город, Дата. Свежая оценка не ниже
  порога сразу встаёт в таблицу на своё место; выделенная строка при этом не сбивается. Колонка места —
  постоянной ширины (150 px): длинный список регионов обрезается «…» (полностью — в карточке), иначе он
  сжимает название вакансии.
- **Справа** — карточка выбранной вакансии из обычных виджетов Qt (подписи и текст, без HTML):
  шапка с названием, компанией и цветной плашкой оценки «N из 10»; факты (город, дата публикации,
  источник); блок «Почему такая оценка» с полосой цвета оценки; списки «Есть · N» (зелёные ✓),
  «Не хватает · N» (красные ✕), «Может отсечь · N» (жёлтые !), без рисков — «✓ Блокеров не найдено».
  Длинное содержимое прокручивается внутри карточки. В нижней полосе карточки — кнопки «Открыть
  вакансию» (открывает `url` в браузере по умолчанию) и «Скрыть» (ставит `hidden = 1` и убирает
  строку из таблицы). Если ничего не выбрано — «Выберите вакансию в списке слева».
- **Кнопка «Резюме»** справа в верхней полосе открывает отдельное немодальное окно с текущим
  `master_cv.md`: сверху путь к файлу, дата изменения и навыки для отсева (`skills.load_skills`), ниже
  само резюме с оформлением Markdown (`QTextBrowser.setMarkdown`, обычный виджет Qt), внизу кнопки
  «Открыть в редакторе» и «Закрыть». Файл перечитывается при каждом открытии окна; если его нет —
  сообщение об этом. Ссылки зелёные: их цвет задаётся в палитре приложения (`style.apply_app_theme`).
- **Отклики.** В карточке найденной вакансии — кнопка «Подался» (между «Открыть вакансию» и
  «Скрыть»): вакансия получает `status = 'applied'` и сегодняшнюю `applied_at` и переходит во вкладку
  «Мои отклики». Там таблица: Отклик (дата), Вакансия, Компания, Статус, Оценка; статус выделен
  цветом: «Ждём ответа» — синий, «Приняли» — зелёный, «Отказали» — красный. Карточка та же, под
  компанией — плашка «Отклик ГГГГ-ММ-ДД · статус», кнопки: «Открыть вакансию», кнопки статусов,
  «Вернуть в найденные» (на случай ошибочного нажатия: статус и дата очищаются; если вакансия
  уже пропала с сайта, в найденных она не появится). Статус можно менять сколько угодно: видны
  кнопки только тех статусов из «Ждём ответа», «Приняли», «Отказали», которые отличаются от текущего.
- **Сколько ждём.** В таблице откликов между «Статус» и «Оценка» — колонка «Ждём, дн.»: сколько дней
  прошло с `applied_at`, только для статуса «Ждём ответа» (у остальных «—»). Если дольше
  `STALE_DAYS = 14` (`config.py`), число в таблице янтарное, плашка в карточке янтарная и с числом дней
  («Отклик ГГГГ-ММ-ДД · Ждём ответа · 21 день»), а под ней подсказка «Больше 14 дней без ответа — пора
  напомнить о себе или закрыть отклик». До этого срока плашка обычная, тоже с числом дней.
- **Заметки.** В карточке отклика под плашкой — поле «Заметки» (обычный многострочный текст).
  Сохраняется само: через полсекунды после последнего нажатия клавиши и при переходе к другой строке.
- **Новые.** В таблице найденных у новой вакансии (`seen = 0`) перед названием стоит «•», название
  жирное; на переключателе — число новых: «Найденные · 21 (+3)» (без «(+0)», если новых нет).
- **Уже подавались.** Если у найденной вакансии та же компания и то же название, что у какого-то
  отклика (сравнение без учёта регистра и лишних пробелов, как при удалении дублей), в таблице перед
  названием стоит «↻», а в карточке — жёлтая плашка «Вы уже подавались на … ГГГГ-ММ-ДД — статус: …».
  Вакансия при этом не скрывается: это может быть новая позиция с тем же названием.
- **Выравнивание:** единый отступ 12 px от краёв окна и между блоками; таблица и карточка деталей
  начинаются и заканчиваются на одном уровне; заголовки колонок выровнены по тексту ячеек.

**Оформление:** тёмная тема с зелёным акцентом; все цвета и стили — в `style.py`. Таблица и детали —
карточки со скруглёнными углами, строки таблицы без сетки, через одну подкрашены. Оценка выделена
цветом: 8–10 — зелёный, 7 — синий, 5–6 — янтарный; в деталях — цветная плашка. Включена тёмная схема
Qt (`setColorScheme(Dark)`), чтобы заголовок окна, полосы прокрутки и диалоги тоже были тёмными.

Обновление запускается автоматически сразу после показа окна. Когда оно заканчивается, список
перечитывается из базы, чтобы сразу убрать вакансии, которые пропали из источника или отсеяны по месту.

**Закрытие окна.** Несохранённая заметка дописывается в базу, все оценённые вакансии отмечаются
просмотренными (`seen = 1`). Фоновый поток запущен как daemon, поэтому окно закрывается сразу, не дожидаясь
текущего запроса к модели. Если модель была загружена, запускается `lms unload` без ожидания
завершения, затем процесс выходит.

## 8. Ошибки

| Ситуация | Поведение |
|---|---|
| Источник недоступен или вернул ошибку | В строке состояния «<источник>: ошибка …», его вакансии в базе не меняются, остальные источники работают |

## 11. Проверка

**Автотесты (pytest, без сети и LM Studio):**

- `sources`: разбор сохранённых образцов каждого источника в `Job`; отбор Development у Working
  Nomads; удаление дублей с учётом приоритета.
- `skills`: разбор навыков из образца резюме; совпадения целым словом (`Git`/`GitLab`,
  `SQL`/`T-SQL`/`MySQL`).
- `db`: `upsert` сохраняет оценку и `hidden`; деактивация вакансий, пропавших из источника;
  очередь после смены `cv_hash`; скрытые вакансии не попадают ни в очередь, ни в список; порог и
  сортировка списка; отклик уходит из найденных в «Мои отклики», не попадает в очередь, остаётся после
  исчезновения вакансии с сайта и смены ключа; смена статуса; «Вернуть в найденные»; старая база
  без колонок `status`, `applied_at`, `notes`, `seen` дополняется при `init()` с сохранением данных,
  а имевшиеся вакансии становятся просмотренными; новые строки — непросмотренные; «отметить все
  просмотренными»; заметка сохраняется и читается со списком откликов.
- `llm`: `evaluate()` с подменённым HTTP-запросом — что уходит в модель (резюме, обрезанное
  описание) и что возвращается (`score` — целое).
- `window`: окно без экрана (`QT_QPA_PLATFORM=offscreen`) — порядок и порог строк, выделение не
  сбивается при новой оценке, «Скрыть» убирает строку; «Подался» переносит строку во вкладку откликов
  и обновляет числа на переключателе; кнопки статуса и «Вернуть в найденные»; пометка «↻» и плашка
  «Вы уже подавались» у вакансии с той же компанией и названием; пометка «•» и «(+N)» у новых, в том
  числе пришедших во время обновления; видны кнопки только других статусов; колонка «Ждём, дн.» и
  янтарная подсветка после `STALE_DAYS`; заметка сохраняется и подставляется при повторном выборе;
  закрытие окна отмечает всё просмотренным. Число дней и склонение «день / дня / дней» — чистые
  функции с явной датой «сегодня».

**Вручную:**

- Модель: оценить 3–5 реальных вакансий, посмотреть ответы и время. Цель — в среднем не больше
  ~15 с на вакансию, модель целиком в видеопамяти (`lms ps`, `nvidia-smi`).
- Приложение: двойной клик по ярлыку → окно без консоли, обновление началось само, список
  заполняется по ходу оценки, окно отзывчиво; повторное «Обновить» оценивает только новые
  вакансии; после правки `master_cv.md` все вакансии оцениваются заново; «Скрыть» и «Открыть
  вакансию» работают; после закрытия окна процесса нет, видеопамять освобождена.

## 13. Анализ требований (вкладка Insights)

Цель — решить, что учить и что дописать в резюме. Вкладка показывает два списка: чего чаще всего не
хватает и что чаще всего требуют.

**Выборка.** Разборы всех вакансий с `active = 1`, `hidden = 0`, без отклика, оценённых по текущему
ключу, — та же выборка, что в итоге «Done: … out of N evaluated». Модель повторно не вызывается.

**Источник требований** — списки `have` и `missing` из разборов модели. Текст объявлений не
используется: в нём много шаблонных слов (например, «security» из фраз о приватности).

**Словарь** (`insights.py`, `REQUIREMENTS`): около 80 требований «название → варианты написания»
(регулярные выражения). Совпадение — целым словом без учёта регистра: `(?<![\w#+.])вариант(?![\w#+])`,
поэтому `C#` не совпадает с `C`, а `.NET` и `C++` распознаются. Пункт может совпасть с несколькими
требованиями: «cloud platforms (aws/gcp/azure)» → Cloud (any), AWS, GCP, Azure. Группы: языки
(Python, Java, C#/.NET, C/C++, Go, TypeScript, JavaScript…), фреймворки (Django, Flask, FastAPI, React,
Spring…), данные (SQL, PostgreSQL, MongoDB, Spark…), инфраструктура (Docker, Kubernetes, Linux, CI/CD,
AWS, Azure, GCP, Cloud (any), Terraform…), AI (Machine learning, LLM/AI, AI coding tools), практики
(Testing, REST API, Microservices, Agile/Scrum…), не технические (Experience 2+ years, Czech, German,
English C1+, Degree, Project management).

**Что есть в резюме.** Требование считается вашим, если какой-то его вариант встречается в строках
раздела `## Skills` — тех же, что читает отсев (`skills.py`): строки `Concepts` и `In progress`
навыками не считаются. Разбор раздела Skills — в одном месте для отсева и для этой вкладки.

**Список «Most often missing».** Для каждого требования — число вакансий, в чьём `missing` есть хотя
бы один пункт с ним. Требования из резюме сюда не попадают: «commercial Python experience» — нехватка
опыта, а не навыка. По убыванию числа, при равенстве — по названию; первые 20.

**Список «Most often required».** Для каждого требования — число вакансий, где оно есть в `have` или
`missing`, и сколько из них засчитано вам (есть в `have`). Порядок тот же, первые 20. Требования из
резюме отмечены «✓» и зелёным.

**Нераспознанные** — число пунктов `missing`, не совпавших ни с одним требованием.

Каждая вакансия даёт требованию не больше одного очка в каждом списке. Отсутствующие `have` или
`missing` считаются пустыми.

**Окно.** Переключатель в верхней полосе — из трёх частей: «Found · N (+K) | My applications · M |
Insights». На вкладке Insights вместо таблицы и карточки — две карточки рядом:

- слева «MOST OFTEN MISSING», подпись «In how many jobs the model listed it under Missing»; строка —
  название, красная полоса, число;
- справа «MOST OFTEN REQUIRED», подпись «Green: counted as yours · red: missing»; полоса из зелёной
  (засчитано) и красной (не хватает) частей, число.

Длина полосы пропорциональна числу, самая длинная в карточке — 220 px. Внизу — «Based on N evaluated
jobs · U missing items not recognised». Пересчёт — при каждом открытии вкладки и в конце обновления,
если вкладка открыта. Резюме не читается (нет настроек или файла) — вместо карточек «Can't read your CV — check it in Settings»;
оценённых вакансий нет — «Nothing evaluated yet».

**Проверка.** Тесты `insights`: варианты написания (`k8s` → Kubernetes), `C#` не засчитывается как
C/C++, одна вакансия — одно очко, требования из резюме не попадают в «missing», подсчёт засчитанного,
нераспознанные пункты; общий разбор строк Skills. Тесты окна: третья вкладка показывает карточки,
возврат на Found возвращает таблицу и карточку, пересчёт после обновления, надписи без резюме и без
оценок. Вручную: доля распознанных пунктов `missing` на реальной базе — не меньше 70 %; скриншот вкладки.

## 14. Свежесть и базовые удобства

**Зачем.** Приложение собираются дать друзьям-айтишникам. Главная беда обычных сайтов с вакансиями —
«мёртвые» объявления: алгоритм поднимает популярные, а не новые, и человек листает то, на что давно
набрали. Сила этого приложения — свежее и живое, поэтому базовые функции строятся вокруг свежести.
Плюс несколько мелочей, без которых любое подобное приложение выглядит недоделанным.

**Цели:** с первого взгляда видно, насколько вакансия свежая; «освежённые» старые вакансии не выдают
себя за новые; старое легко убрать из вида; по отклику видно, что вакансию, похоже, закрыли (там, где это
можно знать честно); простые ожидаемые удобства (поиск, описание в карточке, оставшееся время оценки,
защита от случайного закрытия, отмена «Hide»).
**Не цели:** сортировка кликом по заголовкам колонок, сохранение выбранных фильтров между запусками
(появится вместе с окном Settings на шаге 2), новые сайты, изменение оценки.
**Анти-цели:** ничего из этого не должно запускать переоценку или менять ключ оценки; фильтры не
должны прятать вакансии так, что человек не понимает, почему список пуст.

### 14.1. Возраст вакансии

- **Дата вакансии** для возраста, фильтра свежести и порядка «Newest first» — более ранняя из двух:
  `published` (что говорит сайт) и `first_seen` (когда приложение впервые увидело эту вакансию, 14.7).
  Так вакансия, которой сайт обновил дату, не становится «новой».
- Колонка «Date» в таблице найденных превращается в «Posted»: вместо `YYYY-MM-DD` — «today»,
  «1 day ago», «N days ago» (от даты вакансии до сегодняшней даты). Нет ни одной даты — «—».
- Вакансия старше `STALE_JOB_DAYS = 21` (новая настройка в `config.py`) — текст строки приглушён
  (цвет `muted`), но не скрыт.
- В карточке факт «Published» показывает дату с сайта и её возраст: «2026-10-14 (3 days ago)».

### 14.2. Фильтры в шапке списка найденных

Таблица найденных стоит в общей рамке-карточке (как карточка справа) вместе со своими фильтрами, поэтому
список и карточка по-прежнему начинаются и заканчиваются на одном уровне. Вид выбран по скриншотам.

- **Шапка карточки** (одна строка, все элементы одной высоты, 32 px):
  - поле поиска с подсказкой «Search title, company or location» — фильтр по подстроке без учёта
    регистра в названии, компании и месте; применяется сразу при вводе;
  - сегменты свежести «7d · 14d · 30d · All» (подсказки при наведении — «Last 7 days», «Last 14 days»,
    «Last 30 days», «Any time»); по умолчанию «30d»; считается по дате вакансии (14.1); вакансии без даты
    проходят любой фильтр;
  - сегменты порядка «Best · Newest»: «Best» — как сейчас (оценка ↓, дата ↓), «Newest» — дата ↓, оценка ↓;
    по умолчанию «Best».
- **Под таблицей в той же карточке** — серая строка «12 of 25 shown», только если фильтр что-то скрыл.
- Шапка и строка видны только на вкладке Found; на «My applications» таблица откликов выглядит как прежде.

Фильтры и порядок только меняют, какие строки видны и в каком порядке; база и оценки не меняются.
Переключатель показывает число видимых строк («Found · 12 (+2)»). Если после фильтров не осталось ни
одной строки, вместо таблицы — «No jobs match the filters». Выделение строки при смене фильтра
сохраняется, если строка осталась видна, иначе карточка пустеет. Новые оценки во время обновления
встают в список с учётом фильтров и порядка.

### 14.3. Описание вакансии в карточке

В конце карточки (после списков) — раздел «DESCRIPTION» с кнопкой «Show description» / «Collapse»
(не «Hide», чтобы не путать с кнопкой, которая скрывает вакансию); по умолчанию свёрнут. Развёрнутый — полный текст описания (`description` из базы, обычный текст), выделяемый.
Описание читается из базы при выборе строки (`db.description(url)`), а не хранится во всех строках
списка. У откликов — то же самое.

### 14.4. Сколько осталось и закрытие во время обновления

- Во время оценки строка состояния: «Evaluated 40 of 211 · ~25 min left». Оценка времени — среднее
  время одной вакансии в текущем проходе, умноженное на оставшееся число; показывается после трёх
  оценённых вакансий, до этого — просто «Evaluated N of M». Минуты округляются вверх; меньше
  минуты — «<1 min left».
- Если закрыть окно, пока идёт обновление (загрузка или оценка), появляется вопрос «A refresh is in
  progress. Close anyway? Jobs scored so far are saved.» с кнопками «Close» и «Keep open». «Close» —
  закрытие как сейчас (модель выгружается), «Keep open» — окно остаётся.

### 14.5. Отмена «Hide»

После «Hide» внизу по центру над списком (не перекрывая кнопки карточки) на 10 секунд появляется
плашка «Hidden: <название>» с зелёной кнопкой «Undo».
«Undo» возвращает вакансию (`hidden = 0`, `db.unhide(url)`) и выделяет её. Новое скрытие заменяет
предыдущую отмену; через 10 секунд надпись и кнопка исчезают.

### 14.6. «Похоже, закрыли» в откликах

Отсутствие вакансии в выдаче не всегда значит, что её закрыли: Working Nomads отдаёт только последние
~50 вакансий, у Himalayas мы берём 10 страниц свежих, старые из них вытесняются, оставаясь открытыми.
Поэтому пометка ставится только там, где источник отдаёт свой список целиком: `FULL_LIST_SOURCES =
("Jobicy", "Úřad práce")` в `config.py`. (2026-10-18: junior.guru убран — все его вакансии взяты с других
сайтов, и он убирает часть из них, пока они ещё открыты; найдено автором на вакансии 2N.)

**Пропавшие найденные вакансии (2026-10-18).** Вакансия, которую источник перестал показывать, ещё
`config.GONE_DAYS` = 7 дней остаётся в списке найденных: серая, в колонке Posted «· no longer listed», в
карточке — «No longer listed on <source> since <date>: it may be filled, or the site just dropped it. Open
the job to check.» Дата — колонка `gone_at` (ставится при пропаже, снимается при возвращении). Вакансия,
которую просто перестали искать (другой город, выключена удалёнка), уходит сразу (`sources.still_fetched`).
При обновлении базы неактивные вакансии, впервые увиденные за последние 30 дней, считаются пропавшими в этот
день, более старые — давно.

`db.list_applied()` отдаёт и `active`. Отклик помечается, если одновременно: `active = 0`, источник в
`FULL_LIST_SOURCES`, и в базе нет активной вакансии с той же компанией и названием (`same_job_key`) —
иначе её просто показывает другой сайт. Тогда:

- в таблице откликов перед названием — «⊘ », название серым;
- в карточке под плашкой отклика — серая строка «No longer listed on <source> — probably filled».

Это только пометка; статус отклика не меняется.

### 14.7. Пометка «reposted»

Обычные сайты «освежают» старые вакансии: обновляют дату или перевыкладывают под новой ссылкой.

- Новая колонка `first_seen` (дата `YYYY-MM-DD`): ставится при первой записи вакансии в базу и больше не
  меняется (`save_jobs` её не трогает). Для новой ссылки, у которой в базе уже есть вакансия с той же
  компанией и названием (любая — активная, скрытая, отклик), `first_seen` берётся самый ранний из них.
- При добавлении колонки в старую базу `first_seen` = `published` (или сегодняшняя дата, если `published`
  пустая), чтобы в первый день не было ложных пометок.
- Вакансия помечена «reposted», если `published` позже `first_seen` больше чем на 2 дня (сайт выдаёт её
  за более новую, чем приложение её знает). В таблице найденных — маленькое серое «· reposted» после
  возраста в колонке «Posted»; в карточке к факту «Published» добавляется «· first seen 34 days ago».

### 14.8. Проверка

Тесты: дата вакансии — более ранняя из `published` и `first_seen`; возраст и склонение («today»,
«1 day ago», «5 days ago», «—»), приглушение после `STALE_JOB_DAYS`; поиск по названию / компании / месту,
фильтр свежести (по дате вакансии; без даты проходит), оба порядка, «N of M shown», надпись при пустом
результате, выделение при смене фильтра, новая оценка во время обновления с учётом фильтра; описание
свёрнуто, разворачивается и подставляется при смене строки; оценка времени (по подменённому времени),
вопрос при закрытии во время обновления (обе кнопки) и без вопроса без обновления; «Undo» возвращает
вакансию, исчезает через 10 секунд, новое скрытие заменяет отмену; «похоже, закрыли» — есть для
Jobicy / Úřad práce, нет для junior.guru / Himalayas / Working Nomads и нет, если та же вакансия активна на другом
сайте; `first_seen` ставится один раз, наследуется от вакансии с той же компанией и названием, миграция
без ложных пометок, «reposted» после сдвига `published` больше чем на 2 дня. Вручную — скриншоты Found с
панелью и карточки с описанием.

**Решения исполнителя (не обсуждались с автором, можно менять):** число «(+K)» и «N of M shown» считают
видимые строки; вакансии без даты в «Newest first» — в конце; дата в будущем показывается как «today»;
приглушённые строки сохраняют цвет оценки; развёрнутое описание при выборе другой строки остаётся
развёрнутым; расположение фильтров и «Undo» выбрано по скриншотам (вариант «фильтры в шапке карточки списка»).

## 15. Настройки и мастер первого запуска

**Зачем.** Приложение хотят дать друзьям-айтишникам. Сейчас оно сшито под автора: его город, профессия
(«python»), уровень, языки и то, что ему не нужно разрешение на работу в Чехии, зашиты в `config.py` и
прямо в текст правил оценки (`llm.RULES`), а навыки для отсева читаются из раздела `## Skills` в строгом
формате. Для друга оценки были бы неверными, а настроить всё он смог бы только правкой кода.

**Цели:** при первом запуске мастер проводит по короткому списку и после него можно сразу искать; всё
введённое потом меняется в окне Settings; ничего личного об авторе не остаётся в коде; резюме — любой
текст или PDF, навыки приложение находит само, человек только поправляет; ничего не надо придумывать
самому (никаких ключевых слов) — только выбрать из готового.
**Не цели:** другие страны, кроме Чехии (сайты и фильтры остаются чешскими и удалёнными); выбор и
скачивание модели (шаг 3); облачные модели; резюме в .docx (сохранить как PDF); несколько профилей;
разрешение на работу (не нужно); пороги и сроки в окне (остаются значения по умолчанию).
**Анти-цели:** другу не нужно открывать файлы проекта; данные автора (вакансии, оценки, отклики,
заметки) не теряются при обновлении; полная переоценка никогда не запускается без предупреждения; окно
настроек не выглядит скомканным.

### 15.1. Что хранится

Настройки — в той же базе `jobs.db`, отдельной таблицей `settings` с одной строкой (JSON). Поля:

| Поле | Что это | По умолчанию для нового пользователя |
|---|---|---|
| `cv_path` | путь к файлу резюме (`.md`, `.txt` или `.pdf`) | — (обязательно) |
| `skills` | список навыков для отсева без ИИ | найденные в резюме (15.3) |
| `main_skill` | главный навык, один из `skills`: по нему ищут удалённые сайты | язык программирования, который чаще всех встречается в резюме (15.3) |
| `city` | город из списка регионов junior.guru (Praha, Brno, Ostrava, Plzeň, Olomouc, Liberec, České Budějovice, Hradec Králové, Pardubice, Zlín, Jihlava, Karlovy Vary, Ústí nad Labem) | Praha |
| `remote` | удалёнка подходит | да |
| `levels` | уровни, на которые человек ищет работу: один или несколько из intern, junior, mid, senior, lead | junior |
| `languages` | языки и уровни (A1, A2, B1, B2, C1, C2, Native); хотя бы один | строка English без уровня (уровень обязателен) |
| `min_score`, `stale_days`, `stale_job_days` | порог, дни до подсказки об отклике, дни до приглушения вакансии; в окне не показываются | 5, 14, 21 |

Резюме перечитывается при каждом обновлении, как сейчас: правка файла даёт переоценку.

### 15.2. Мастер первого запуска

Появляется при старте, **только если настроек нет или в них не хватает обязательного** (так же
открывается у того, чьи настройки сохранены в старом виде, — см. 15.6); заполнен тем, что уже есть. Вид —
одна колонка, сверху «Step N of 4» и полоса прогресса, внизу «Back» / «Next», на последнем шаге
«Start search» (выбрано автором по скриншотам):

1. **Welcome** — одна-две фразы, что делает приложение и что дальше спросят.
2. **Your CV** — выбор файла; под ним найденные навыки «плашками» с крестиком и поле «+ Add skill»;
   «Main skill» — выпадающий список из этих навыков.
3. **What you're looking for** — город, «Remote is fine», «Level»: кнопки Intern / Junior / Mid /
   Senior / Lead, можно включить несколько (хотя бы одна включена).
4. **Languages** — строки «язык — уровень — ×» и кнопка «+ Add language».

«Next» недоступна, пока на шаге не заполнено обязательное. Если закрыть мастер, не дойдя до конца,
приложение закрывается (без настроек искать нечего), ничего не сохраняется. После «Start search»
настройки сохраняются, главное окно запускает обновление.

### 15.3. Навыки из резюме

Текст резюме: `.md` / `.txt` — как есть; `.pdf` — текст страниц (`pypdf`). Навыки ищутся словарём
`insights.REQUIREMENTS` (тот же, что во вкладке Insights, без нетехнических групп: опыт, языки, диплом,
предметная область, soft skills) и показываются плашками; человек убирает лишнее крестиком и добавляет
своё (поле «+ Add skill», Enter добавляет). Отсев без ИИ и пометка «есть в резюме» во вкладке Insights
берут навыки из настроек. Файл не читается — понятное сообщение под полем файла, навыки можно ввести
вручную. Навыки не уходят в модель и не входят в ключ оценки.

**Главный навык** выбирается из навыков. Догадка по умолчанию: из языков программирования словаря
(Python, Java, JavaScript, TypeScript, C#, C++, Go, PHP, Ruby, Kotlin, Swift, Rust, Scala и т. п. —
какие есть в словаре) берётся тот, что чаще всех встречается в тексте резюме; если ни одного нет —
первый навык. Убрали навык, который был главным, — догадка выбирается заново из оставшихся.

### 15.4. Окно Settings

Кнопка «Settings» в верхней полосе (рядом с «My CV»). Вид — вариант B (выбран автором по скриншотам):
слева меню из трёх разделов (Your CV / What you're looking for / Languages), справа — один раздел:
крупный заголовок, строка-пояснение и поля те же, что в мастере; внизу справа «Cancel» и «Save».
«Save» недоступна, пока не хватает обязательного; рядом серым — чего именно («Still needed: …»).

Если изменились поля, которые влияют на оценку (резюме, город, удалёнка, уровни, языки), перед
сохранением — вопрос «All jobs will be scored again (about N min). Save?» (N — по числу вакансий, которые
пойдут на оценку, и ~8 с на вакансию). Навыки и главный навык сохраняются без вопроса. После сохранения
список перечитывается; если изменилось что-то кроме порогов (то есть что искать, как отсеивать или как
оценивать) — сразу запускается обновление. Пока идёт обновление, кнопка «Settings» недоступна
(обновление читает настройки один раз в начале).

### 15.5. Правила оценки и поиск из настроек

- `llm.RULES` — шаблон: город, удалёнка, уровни и языки подставляются из настроек. Ключ оценки включает
  готовый текст правил, поэтому смена этих полей сама даёт переоценку. Навыки и главный навык в правила
  не попадают. Про разрешение на работу правила ничего не говорят.
- **Нейтральные формулировки** (проверены на 40 вакансиях, см. журнал плана настроек): «You help a
  candidate…»; блокер «основной язык или область вакансии другие, чем у кандидата по резюме»; близкие
  навыки — общим правилом с примерами из разных стеков.
- **Уровни.** У каждого уровня свои слова для правил: какой опыт для него — блокер, что значит «выше
  уровня» и «совсем не тот уровень» (intern: требуется коммерческий опыт; junior: 2+ года или
  mid/senior; mid: 5+ лет или senior/lead; senior: lead/principal или 10+ лет; lead: director/executive).
  При нескольких выбранных: кандидат ищет «internship or junior roles» (названия выбранных через «or»);
  верхняя полоса шкалы — роли выбранных уровней; блокер по опыту и полосы «выше уровня» — по самому
  высокому из выбранных; роль заметно ниже самого низкого из выбранных (для mid и выше) — слабое
  совпадение. Для intern и junior остаётся «недостающее можно выучить на работе».
- **Языки.** В правилах перечислены все языки с уровнями («Languages: English B2, Czech A2, Russian
  native»); блокер — вакансия требует язык, которого у кандидата нет на нужном уровне; не проблема —
  каждый язык на уровне кандидата, если не требуется выше.
- **Проверка перед переходом** (как в разделе 12): на копии базы сравнить хранимые оценки и новые правила
  на ~40 вакансиях с настройками автора; средняя оценка не сдвигается больше чем на 0,7, число
  подходящих (≥ 5) — не больше чем на 3 из 40; иначе правится формулировка, а не шкала. После перехода у
  автора одна полная переоценка (с предупреждением).
- **Поиск.** Himalayas — один запрос по главному навыку, до 10 страниц (как было до настроек с
  `python`); `seniority` — объединение по выбранным уровням: intern → Entry-level; junior → Entry-level,
  Mid-level; mid → Mid-level, Senior; senior → Senior; lead → Senior, Manager. Jobicy и Working
  Nomads — как сейчас; junior.guru — фильтр по выбранному городу (регион) или удалёнке.
- **«Remote is fine» выключено:** удалённые сайты (Himalayas, Jobicy, Working Nomads) не запрашиваются, а
  их вакансии в базе становятся неактивными; у junior.guru берутся только вакансии выбранного города.
- Порог, дни до подсказки и до приглушения берутся из настроек вместо `config.py`.

### 15.6. Переход для автора

Значений автора в коде нет. Если настроек нет, но в папке проекта есть `master_cv.md`, мастер подставляет
только резюме (этот файл), найденные навыки и догадку главного навыка. У кого настройки сохранены в
старом виде (с ключевыми словами, двумя языками и разрешением на работу), мастер открывается при
запуске с тем, что подходит (резюме, навыки, город, удалёнка); остальное вводится один раз. На последнем
шаге мастер предупреждает, что если в базе уже есть оценки, все вакансии будут оценены заново.

### 15.7. Код

- `job_finder/settings.py`: загрузка и сохранение настроек, значения по умолчанию, проверка обязательных
  полей, чтение текста резюме, поиск навыков и догадка главного навыка.
- `job_finder/settings_window.py`: мастер и окно Settings (общие виджеты полей: плашки навыков, уровни,
  строки языков). Раскладка «плашек» с переносом — отдельный маленький класс (где — решает исполнитель).
- `window.py` не растёт ради этого: только кнопка, вызов окна и пороги из настроек.

### 15.8. Проверка

Тесты: сохранение и загрузка настроек; мастер появляется без настроек и при неполных настройках и не
появляется при полных; «Next» недоступна без обязательного; закрытие мастера без «Start search» не
сохраняет настройки; навыки из текста и PDF; догадка главного навыка (самый частый язык
программирования, иначе первый навык); плашки: добавить, убрать, убрать главный; уровни: несколько
сразу, последний не выключается; языки: добавить строку, убрать, строка без уровня — не хватает
обязательного; «Still needed» в Settings; правила подставляют город, уровни и языки, не упоминают
разрешение, ключ оценки меняется от них и не меняется от навыков и главного навыка; вопрос о переоценке
только при «влияющих» полях; Himalayas ищет по главному навыку до 10 страниц и берёт `seniority` из
уровней; без удалёнки удалённые сайты не запрашиваются; junior.guru фильтрует по городу; набор тестов
завершается без падения процесса (код выхода 0). Вручную — сравнение правил на ~40 вакансиях (15.5);
скриншоты мастера и окна Settings.

### 15.9. Что изменилось после проверки автором (2026-10-17)

Первая версия (ключевые слова 1–3, английский и чешский отдельными полями, разрешение на работу, уровни
junior/mid, раздел Advanced в одной длинной форме) не понравилась при проверке: ключевые слова трудно
придумать, а выдача Himalayas упала вдвое (198 → 102 — десять страниц делились между тремя словами);
форма скомкана и с лишним; два языка и два уровня не подходят для общего доступа. Заменено на главный
навык из списка, языки списком, пять уровней с выбором нескольких, окно с меню слева; разрешение на
работу и Advanced убраны из окна.

**Решения исполнителя (не обсуждались с автором):** нейтральные правила с проверкой на ~40 вакансиях;
без удалёнки удалённые сайты не запрашиваются; навыки вне ключа оценки; в коде нет значений автора;
хранение в таблице `settings` базы; `pypdf` для PDF; список городов — регионы junior.guru; закрытие
незаконченного мастера закрывает приложение; оценка времени переоценки — ~8 с на вакансию; мастер при
неполных настройках; догадка главного навыка по частоте языков программирования; соответствие уровней
фильтру Himalayas; список языков в выпадающем поле можно дополнить своим; «Settings» недоступна во
время обновления; новое обновление после сохранения при любых изменениях, кроме порогов.

## 16. Трей, автообновление, уведомления; старые вакансии и зарплата

**Зачем.** Чтобы не открывать приложение каждый день: оно само ищет новые вакансии и сообщает о хороших;
первая оценка у друзей короче; в карточке видна зарплата, если сайт её дал. Автор попросил решить детали
самому и проверить потом — все решения ниже исполнителя.

**Не цели:** автозапуск вместе с Windows; зарплата из текста описания (только поля сайтов); настройка
интервала и порога уведомлений в окне (значения в `config.py`).

### 16.1. Старые вакансии не оцениваются
Вакансия, которой по дате с сайта (`published`) больше 30 дней (`config.OLD_JOB_DAYS`), не уходит в модель:
её всё равно прячет фильтр свежести по умолчанию (30 дней); при «All» неоценённые старые вакансии просто не видны. Вакансия без даты оценивается, как раньше. В базе такие
вакансии остаются (для пометок «reposted» и «закрыта»). Ключ оценки и правила не меняются.

### 16.2. Зарплата
Jobicy (`salaryMin`, `salaryMax`, `salaryCurrency`, `salaryPeriod`) и Himalayas (`minSalary`, `maxSalary`,
`currency`, `salaryPeriod`) иногда отдают вилку; junior.guru и Working Nomads — нет. Текст вида
«$2,000–3,000 / month» (символ для USD/EUR/GBP, иначе код валюты после чисел; «from …» / «up to …», если
есть только одна граница) хранится в новой колонке `salary` и показывается строкой «Salary» в фактах
карточки; нет зарплаты — строки нет. В модель зарплата отдельно не передаётся.

### 16.3. Трей и автообновление
- Пока приложение запущено, в трее иконка Job Finder. Крестик окна прячет его в трей (приложение работает
  дальше); в первый раз за запуск — всплывающая подсказка, как его закрыть. Меню иконки: «Open Job Finder»,
  «Refresh now», «Quit»; щелчок по иконке открывает окно. «Quit» — прежнее закрытие (вопрос, если идёт
  обновление; выгрузка модели). Нет трея в системе — крестик закрывает приложение, как раньше.
- Спрятать окно = закрыть его по-старому для пометок «новая»: всё увиденное перестаёт быть новым.
- Раз в 3 часа (`config.AUTO_REFRESH_HOURS`) приложение само запускает обновление. Если обновление уже идёт —
  пропуск до следующего раза. Если запущена полноэкранная игра или презентация (Windows сообщает «занят»),
  обновление откладывается на 15 минут, пока не освободится: игра и модель делят видеопамять. То же
  проверяется между вакансиями: игра запустилась посреди оценки — оценка останавливается, модель
  выгружается, остальное оценивается через 15 минут.
- Одно обновление за раз: таймер, меню трея и Settings не запускают второе, пока идёт первое; если в Settings
  поменяли поиск во время обновления, после него запускается ещё одно.
- Повторный запуск ярлыка, пока приложение работает (в том числе спрятанным в трей), показывает его окно.

### 16.4. Уведомления
После обновления (ручного или автоматического), если окно спрятано, свёрнуто или не активно, а среди
вакансий, оценённых за это обновление, есть новые (ещё не виденные) с оценкой не ниже 7
(`config.NOTIFY_SCORE`), — уведомление Windows из трея: «N new job(s) with a score of 7+». Щелчок по нему
открывает окно. Переоценка уже виденных вакансий (после смены настроек) уведомления не даёт.

### 16.5. Проверка
Тесты: старая вакансия не уходит в модель, без даты — уходит; разбор зарплаты из обоих сайтов и её строка в
карточке (нет зарплаты — строки нет), колонка добавляется в старую базу; крестик с треем прячет окно и
помечает виденное, без трея — закрывает; «Quit» закрывает по-старому; автообновление: идёт обновление —
пропуск, «занят» — откладывается, иначе запускается; уведомление только для новых вакансий 7+ и только при
неактивном окне. Вручную — автор пробует трей и уведомление у себя.

## 17. Новые источники: Úřad práce, Remote OK, We Work Remotely

**Зачем.** Больше вакансий, особенно офисных в своём городе: сейчас их даёт только junior.guru. Разведка
2026-10-18 (автор попросил посмотреть самому и одобрил выбор): у jobs.cz, prace.cz, LinkedIn, StartupJobs,
Cocuma открытого API нет (только разбор страниц — против их правил и ломается); Jooble требует ключ у
каждого пользователя и обрезает описания; Arbeitnow — немецкий рынок. Берём три открытых источника.

### 17.1. Úřad práce ČR (открытые данные MPSV)
- Файл всех вакансий биржи труда: `https://data.mpsv.cz/od/soubory/volna-mista/volna-mista.json`
  (~190 МБ, обновляется раз в день, ~40 000 вакансий, из них ~1 000 IT). Скачивается с `If-None-Match` /
  `If-Modified-Since`: если файл не менялся (сервер отвечает 304), берётся сохранённая выборка.
- Разбор по одной вакансии, без загрузки всего файла в память (иначе ~1,7 ГБ). Остаются только IT-профессии
  (CZ-ISCO 25…, 351…, 1330…). Край вакансии: из адреса рабочего места, иначе по коду обце или района (их
  край узнаётся из адресов других вакансий того же файла); «вся ČR» подходит любому краю; неизвестный край —
  вакансия отбрасывается. Выборка (IT по всем краям) хранится в `cache/uradprace.json` (папка в
  `.gitignore`), поэтому смена города не требует новой загрузки. Ошибка сети при сохранённой выборке —
  берётся она; без выборки — ошибка источника, как у других сайтов.
- Берутся вакансии края выбранного города (Praha → Praha; Brno → Jihomoravský; и т. д. для 13 городов).
  Это офисная работа: источник запрашивается и при выключенной удалёнке. Источник отдаёт полный список
  (пометка «закрыта» честная), как Jobicy; «ещё ищется» — пока выбран тот же край.
- Вакансия: ссылка `https://up.gov.cz/volna-mista-v-cr#/volna-mista-detail/<portalId>`, название —
  требуемая профессия, компания — работодатель, место — «Prague» для Праги, иначе «<город> region», дата —
  дата внесения, описание — уточняющая информация, зарплата — «от–до CZK / month».
- Правило «не оценивать старше 30 дней» действует и здесь.

### 17.2. Remote OK
`https://remoteok.com/api` (первый элемент — условия, пропускается). Название, компания, «Remote: <место>»,
дата, описание, зарплата (USD в год). Только удалёнка. Условия API — ссылка на вакансию на Remote OK и
название источника — выполняются (ссылка «Open job» и строка «Source»); логотип не используется.

### 17.3. We Work Remotely
RSS категорий programming, full-stack, back-end, front-end, devops-sysadmin
(`https://weworkremotely.com/categories/remote-<категория>-jobs.rss`), повторы по ссылке убираются.
Заголовок «Компания: Должность», регион → «Remote: <регион>». Только удалёнка.

### 17.4. Порядок и проверка
Порядок (он же приоритет при удалении дублей): junior.guru, Úřad práce, Himalayas, Jobicy, Working Nomads,
Remote OK, We Work Remotely. Тесты: потоковый разбор (файл кусками, граница внутри вакансии), фильтр IT и
края (адрес, обец, район, «вся ČR»), 304 → выборка из кэша, ошибка сети → кэш, поля вакансии и зарплата;
разбор Remote OK и RSS; удалённые сайты не запрашиваются без удалёнки, Úřad práce — запрашивается;
«закрыта» для Úřad práce только при том же крае. Вручную — один реальный запуск без оценки: сколько
вакансий даёт каждый источник.

**Решения исполнителя:** набор IT-кодов CZ-ISCO; край через адреса того же файла; кэш выборки на диске;
«<город> region» для краёв кроме Праги; категории RSS; порядок источников; источник Úřad práce не зависит
от удалёнки.

## 18. Установщик для друзей, проверка LM Studio, модель по видеопамяти

**Зачем.** Друг без Python должен поставить приложение одним файлом и понять, чего не хватает (LM Studio,
модель). Автор попросил решить самому; проверку маленькой модели на вакансиях не делаем — в README честно
пишем, что она слабее и оценки могут немного отличаться.

**Не цели:** цифровая подпись (Windows покажет «неизвестный издатель» — README объясняет); автообновление
(проверка новой версии — раздел 19);
выбор модели в окне; модель 14B; macOS/Linux.

### 18.1. Установщик
- `JobFinder-Setup.exe` — один файл (PyInstaller): внутри собранное приложение (PyInstaller, папка с
  `Job Finder.exe`, Python и библиотеки уже внутри). Запуск: файлы — в `%LOCALAPPDATA%\Programs\Job Finder`
  (старая версия заменяется), ярлыки «Job Finder» на рабочем столе и в «Пуске», «Uninstall Job Finder» в
  «Пуске»; в конце вопрос «Open Job Finder now?». Приложение запущено — просьба закрыть его (трей → Quit) и
  запустить установку снова.
- `Job Finder.exe --uninstall` (ярлык «Uninstall Job Finder»): вопрос, удаление ярлыков и папки программы;
  данные (база, отклики) остаются, путь к ним называется.
- Сборка — `build.ps1` (только для разработчика; PyInstaller ставится в `.venv`); `build/`, `dist/` — в
  `.gitignore`. Релиз на GitHub публикуется только с согласия автора.

### 18.2. Где лежат данные
Из исходников — папка проекта, как сейчас (у автора ничего не меняется). Установленная версия —
`%LOCALAPPDATA%\Job Finder` (база, журнал, кэш Úřad práce): обновление и удаление программы их не трогают.
Переменная `JOB_FINDER_DATA` задаёт другую папку (для проверок). Блокировка «уже открыто» — одна на
пользователя (`%LOCALAPPDATA%\Job Finder\job_finder.lock`), чтобы версия из исходников и установленная не
работали одновременно с одной моделью.

### 18.3. Окно «Getting ready»
При запуске, до мастера, проверяется: есть ли LM Studio (`lms.exe`; он появляется после первого открытия
LM Studio) и скачана ли нужная модель (`lms ls --llm --json`). Всё есть — окна нет. Иначе — окно со строками
«LM Studio» и «AI model: <название> (your graphics card has N GB)», кнопки «Get LM Studio» (сайт),
«Download model» (`lms get <модель> -y` в фоне, полоса ожидания; скачивание только по нажатию), «Check
again», «Continue» (когда всё есть; иначе «Continue anyway» — приложение откроется, оценка не запустится,
строка состояния скажет почему).

### 18.4. Модель по видеопамяти
Объём видеопамяти — из реестра Windows (`HardwareInformation.qwMemorySize` адаптеров, самый большой).
От 7,5 ГБ (карты на 8 ГБ) или если не удалось узнать — `mistralai/ministral-3-8b` (как сейчас); меньше —
`mistralai/ministral-3-3b`. Поле настроек `model` (пусто = «по видеопамяти»); ключ оценки включает модель,
поэтому у автора (12 ГБ → 8B) ключ прежний. Если в LM Studio под нашим именем загружена другая модель — она
выгружается и грузится нужная.

### 18.5. Проверка
Тесты: папка данных (исходники / установленная / переменная), выбор модели по объёму, чтение объёма из
реестра (подменённого), окно «Getting ready» (нет LM Studio, нет модели, скачивание, всё есть — окна нет),
установка во временную папку из архива и ярлыки (подменённые), удаление; модель в ключе оценки и в загрузке.
Вручную — сборка, запуск установщика во временную папку, запуск собранного приложения с временной папкой
данных.

## 19. Проверка обновлений

**Зачем.** Друзья ставят приложение с GitHub и иначе не узнают, что вышла новая версия. Автор выбрал эту идею
из трёх; детали решены самостоятельно.

- Номер версии — `config.VERSION` (первая с проверкой — `1.1.0`); тег релиза — `v` + тот же номер. Подсказка
  у иконки в трее — «Job Finder 1.1.0».
- Только установленная версия (`config.FROZEN`): версия из исходников обновляется через git.
- При запуске и с каждым автообновлением (раз в 3 часа, даже во время игры — это один маленький запрос) в
  фоне запрашивается `api.github.com/repos/BuisnessCat/cv_job_finder/releases/latest`; черновики и
  предрелизы туда не попадают. Сравниваются числа версии (`1.10.0` новее `1.9.0`); непонятный тег, ошибка
  сети или лимит запросов GitHub — тихо, только запись в журнал.
- Нашлась новее — справа вверху зелёная кнопка «Update to 1.2.0»: открывает страницу последнего релиза
  (адрес постоянный, не из ответа). Окно не впереди (трей) — уведомление Windows, один раз на версию; клик по
  нему тоже открывает страницу.
- Не цели: скачивание и установка самим приложением, список изменений в окне, отключение проверки.
- Проверка: тесты разбора версий и ответа GitHub (подменённого), ошибок сети; кнопка, уведомление один раз,
  проверка с автообновлением, нет проверки из исходников.
